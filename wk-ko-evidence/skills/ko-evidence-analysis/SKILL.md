# 한국 소송 증거·기록 분석 보조

> **긴 작업에서**: 대화가 요약(컴팩션)되면 이 문서는 앞부분만 다시 붙는다. 요약 뒤 작업을 이어 갈 때와 2층·송부로 넘어가기 전에 이 skill을 다시 불러 뒷부분(출력 규칙·scripts·함정·송부)을 읽는다. 진행 상황의 정본은 분석 폴더의 파일(매니페스트·카드·`_작업/전수성.json`)이다.

## 1. 이 skill이 하는 일과 하지 않는 일

기록을 읽어 **분석 산출물**을 만든다. 서면은 쓰지 않는다 — 소장·준비서면·의견서·신문사항·증거설명서·증거의견서는 drafting 4종(민사·형사·행정·자문)이 이 산출물을 입력으로 받아 작성한다. PDF → markdown 변환도 하지 않는다(§3.3). 자문의견서·계약 검토는 대상이 아니다.

이 skill의 가치는 분석 계획이 아니라 절차에 있다: 대용량 기록의 전수 처리와 파일 영속화, 좌표 보존과 기계 역검증, 변환 표식의 전파, 형사 증거목록·권 체계의 해석, drafting으로의 무손실 인계.

결과물의 1차 책임은 변호사에게 있고 출력은 항상 검토 대상이다.

**기록의 취급.** 열람·등사한 기록 사본은 당해 사건·관련 소송 준비 외의 목적으로 제공(전기통신 포함)할 수 없고(형사소송법 제266조의16), 변호사는 직무상 비밀을 누설할 수 없다(변호사법 제26조). 따라서:

- 변환본·카드·산출물은 작업 루트 안에만 둔다. 홈 디렉터리 캐시, 플러그인 폴더, 로컬 지식베이스에 쓰지 않는다. 다른 사건의 산출물로 옮기지 않는다.
- 기록 내용이 세션 밖으로 나가는 경로는 판례·법령 검색어와 웹 검색뿐이다. **검색어는 법률 개념으로 일반화하고 실명·상호·계좌 등 기록의 고유정보를 넣지 않는다.**
- 스크립트의 터미널 출력은 건수·경로만이다. 내용은 분석 폴더의 파일로 받는다.
- 제출하지 않은 자료에도 같은 규율을 적용한다. 기록의 확보 경로(열람·등사, 문서송부촉탁, 의뢰인 보유)는 매니페스트에 적어 두고 사용 범위의 판단은 변호사가 한다.

## 2. 구조 — 2층과 경로 분기

| | 1층 — 기록 다이제스트 | 2층 — 쟁점 분석 |
|---|---|---|
| 성격 | 쟁점·입장 중립. 문서 종류별 스키마 추출 | 쟁점 프레임과 입장에 종속 |
| 착수 | 질문 없이(규모를 1회 통지) | 착수 게이트 3개(§6) |
| 단위 | 문건(카드 한 장) | 쟁점 |
| 재실행 | 1회 작성 후 증분 갱신 | 쟁점이 바뀔 때마다 새 스냅샷 |
| 원칙 | 유불리·신빙성·증거능력 **평가를 적지 않는다**(형식 사실은 적는다) | 인용 직전에 원문 쪽으로 돌아가 확인한다 — **카드는 색인이지 증거가 아니다** |

1층은 무조건 선행한다. 입장이 바뀌어도(변호/고소 대리, 1심/항소심, 형사/관련 민사) 같은 1층을 재사용한다. 원문이 합계 15만 자 미만(`index`의 `색인_전체`)이면 **약식 1층** — 매니페스트·색인과 `원천현황.md`만 — 으로 하고, 2층이 원문을 record 단위로 직접 읽으며 `주의메모.md`도 적는다. 사용자가 1층 전체를 원하면 규모와 무관하게 만든다.

**경로 분기.** 분야가 형사이고 기록 종류가 증거기록·수사기록·공판기록이면 **형사 기록 경로**(증거목록 파서, 권 체계, 목록 ↔ 기록 대조 — `references/03`)를 탄다. 그 밖은 **증거 단위 = 파일**(또는 파일 안의 문건)이고 증거목록·권 검사를 건너뛴다. 변환본에는 분야·기록 종류가 적혀 있지 않으므로 사용자 진술, 폴더·파일명, 표지 쪽, `heading`이 증거목록인 쪽, 면수 도장의 연속으로 판정한다. 단서가 갈릴 때만 묻고, 분명하면 판정 근거를 알리고 진행한다.

**완료의 모양**(1·2층 공통 — 완성 선언의 기준은 여기 하나다):

- **산출물**: 1층 = 분석 폴더의 `원천현황.md`·`타임라인.md`·`인물.md`·`주의메모.md` + `_작업/`(매니페스트·색인·카드 — 약식이면 위와 같고 게이트 ②는 해당 없음), 2층 = 산출물마다 파일 1개(§7).
- **완성 게이트**: ① 입력이 모두 A·A′등급 ② `coverage` 누락·원문 변경 0 ③ `verify` 불일치 0(카드·산출물 전부) ④ 미해결 표식 0(`references/06` — `[마스킹]`은 해소 대상이 아니라 개수만 적는다). 하나라도 못 미치면(스크립트를 못 돌린 경우 포함) 완성이라 하지 않고, 본문 첫머리에 "미완성 — 확인 필요 사항 있음", front-matter `미해결표식`에 종류별 개수를 적어 송부한다.
- **응답**: §11.

## 3. 입력

### 3.1 작업 루트와 폴더

- **작업 루트**는 사용자가 지정한 사건 폴더(없으면 현재 작업 폴더)다. 작업 루트 밖의 기록은 사용자가 경로를 명시했을 때만 더한다.
- 작업 루트와 그 상위의 지침 파일(`CLAUDE.md`·`AGENTS.md`)에 산출물 위치·변환본 위치·열람 금지·수정 제한이 있으면 따른다.
- **분석 폴더**: ① 사용자 지시·지침 파일 → ② 작업 루트 아래에 `_작업/사건세트.json`을 가진 폴더(재개) → ③ 없으면 `{작업 루트}/기록분석/`을 알리고 만든다. 작업 폴더가 없으면 outputs/.
- 변환본·원본에는 쓰지 않는다(반입 복사 제외). 분석 폴더 안에서만 쓰고 고친다. 같은 사건에 분석 세션을 둘 이상 동시에 돌리지 않는다.

### 3.2 입력 발견·게이트·신뢰 등급

`discover`로 `pages/page_*.md` + `_index.md` 서명을 가진 폴더를 찾고(목록 조회만 — 동기화 폴더의 온라인 전용 파일을 내려받지 않는다. 변환본이 한 저장소에 있든 원본 옆에 있든 상관없다), 찾은 폴더마다 `gate`로 등급을 정한다.

| 등급 | 입력 | 허용 범위 |
|---|---|---|
| A | 현행 규격(front-matter 4키) + 게이트 통과 | 전부 |
| A′ | 구 규격(12키) | 키 별칭으로 읽는다. 변환본의 `evidence_ref`는 참고만 하고 증거 단위는 다시 배정한다 |
| B | 규격 밖 변환본을 어댑터로 규격 형태로 만든 것 | 1층·목록 대조·타임라인 초안. 모든 좌표는 추정 — 2층 인용·금액·일자에 "원본 PDF 확인 필요" |
| C | 변환본 없는 직접 첨부(합계 30쪽 미만) | 직접 읽는다. 좌표는 "확인 필요". 30쪽 이상이면 변환을 안내한다 |

입력 규격·반입 규약·게이트 불변식·변환본을 읽을 때의 함정은 `references/01`.

### 3.3 변환과 반입

변환은 이 skill 밖에서 한다(규격 `references/01` §1). 변환 산출 폴더를 사건 폴더로 들일 때는 `import`, 이미 들어와 있는 변환본은 `gate` → `index`로 등록한다. 변환본은 **분류에 묶지 않는 저장소 하나**에 두고, 분류·증거번호·원본 경로는 매니페스트에서만 고친다(반입 규약 `references/01` §3). 원본이 작업 루트에 없으면 함께 넣도록 요청한다 — 끝내 없으면 그 기록의 인용은 "원본 PDF 확인 필요"로 남는다.

## 4. 인용 정확성 게이트

수백 면 기록 분석의 최대 위험은 기록에 없는 내용의 기재다. **좌표 없는 사실은 적지 않는다.**

- **기재 표지 4종**: 직접 인용 `"…"{{p:쪽}}` / 요약(표지 없음 + 좌표) / `[추론]` / `[묘사]`(변환본의 `[사진: …]`·`[그림: …]`·`[도면: …]`은 변환 모델의 묘사이지 기록 기재가 아니다).
- **좌표 태그**: `{{p:record_id#12}}`·`{{p:record_id#12-13}}`(pdf쪽 기준). 카드 안에서는 `{{p:12}}`로 줄이고, 매니페스트의 증거번호가 유일하면 `{{p:갑7#12}}`로 써도 된다. 산출물에는 구조화 값(권 식별자·면수·증거 ID·pdf쪽, ISO 일자)만 두고 표기 문자열("○면", "2026. 6. 10.")은 drafting이 만든다.
- **검증**: 직접 인용은 `verify`, 요약·추론은 2차 패스로 좌표의 원문과 대조, 합계·건수·기간은 `sum`·`profile`(암산 금지), `[불명확]`·핵심 금액·일자는 원본 PDF의 해당 쪽을 직접 재판독(온라인 전용 파일이면 내려받기가 일어남을 먼저 알린다).
- **표식 전파**: 변환 표식(`[불명확: …]`·`[판독불가]`·`[마스킹]`·면수 없는 쪽)과 배정 상태(추정·미배정)는 카드와 산출물에 그대로 옮긴다. 표식이 낀 금액·일자를 타임라인·계산에 단정적으로 쓰지 않는다. 어휘는 `references/06`.

## 5. 1층 워크플로

1. **발견·게이트**: `discover` → `gate`. 규격 밖·구세대 입력은 세대를 붙여 보고한다. `discover`는 변환이 끝나지 않은 폴더와 변환본 없는 PDF도 알려 준다 — 그대로 `원천현황.md`에 옮긴다.
2. **색인**: `index` → `_작업/색인.jsonl`(쪽별 4키·sha256·표식 수)·`구간.jsonl`(같은 제목의 연속 쪽 = 문건 경계의 1차 근거). `printed_page` 뜻의 추정과 `_index.md` 비고 칸도 나온다.
3. **매니페스트 초안**: `_작업/사건세트.json`을 단서로 채우고(`references/02` §1) 규모(쪽수·글자 수)와 약식·대용량 문건 경로 적용 여부를 1회 통지한다. **확인을 기다리는 것은 형사 경로의 권 식별자·`printed_page` 뜻(`assign`의 전제)뿐이다.** 분류·증거번호 등은 추정 표시로 두고 계속한다 — 카드는 위치 키라 값이 확정돼도 다시 쓰지 않는다. 확인은 송부 때 한 번에 받는다.
4. **(형사 경로)** `evlist` → `assign`. 분할 처리에 앞서 주 에이전트가 끝낸다(`references/03`).
5. **문건 경계 확정**: 구간에 보조 단서를 더해 문건을 나눈다(`references/02` §2). 표지·간지·목록은 구조 요소다.
6. **카드 작성**: 문건마다 `_작업/카드/{record_id}/{시작pdf}-{끝pdf}.md`. 문서 종류별 스키마로 추출하고 자유 요약을 하지 않는다(`references/04`). 줄 단위로 구조가 같은 대용량 문건(대화 내보내기 출력물·통화내역·계좌내역)은 `profile`·`sum`으로 프로필만 만든다. 분류를 가리지 않는다(미제출 자료 포함). front-matter의 기계 필드는 다 쓴 뒤 `cardfill`이 채운다. 분할 도구(서브에이전트)가 있으면 권·문건 단위로 나누고(`references/04` §6의 브리프), 없으면 순차 처리한다.
7. **전수성**: `coverage` — 기록 → 카드 누락 0건, (형사) 목록 → 기록 보유 판정, 원문이 바뀐 카드 탐지.
8. **파생물**: `derive`가 `타임라인.md`·`인물.md`를 그대로 쓰고 주의메모 후보를 모은다 — 모델은 `원천현황.md`·`주의메모.md`만 쓴다(`references/04` §5). 약식이면 5~7단계를 건너뛰고 `원천현황.md`만 만든다.
9. **검증**: `verify`로 직접 인용 역검증(§4).

## 6. 2층 워크플로

모드: **(B)** 쟁점 중심 매핑·공백, **(C)** 진술 분석, **(D)** 증거능력 스크리닝(형사), **(E)** 상대방 증거 탄핵·인부 검토.

1층의 `coverage`·`verify`가 통과한 뒤 착수한다. 착수 게이트 3개 — **입장**, **증거 동의 여부**(형사 — 자동으로 채우지 않는다), **쟁점 프레임의 출처**(공소장·판결문·처분서 등 프레임 문건, 조문은 `ko-law-api`) — 가 불명확하면 되묻는다. 분석은 `주의메모.md`에서 출발해 후보 문건의 **원문 쪽을 다시 읽고** 인용한다 — 카드 검색만으로는 놓치므로 원문 grep을 병행한다. 불리한 증거도 빠짐없이 적는다. 보강 수단은 적법한 증거 수집 절차로 한정하고, 허위 증거의 작출이나 증인에 대한 부정한 영향에 해당하는 방안은 적지 않는다. 게이트·분석 절차·판례 확인은 `references/05` §0, 산출물별 열 구성은 같은 문서 §2.

## 7. 출력·파일 규칙

분석 산출물은 표 위주의 내부 작업물이므로 서면 문체 규칙(`wk-ko-legal`의 `shared/기본-문체-규칙.md`)의 개조식·표 제한을 적용하지 않는다.

```
{분석 폴더}/
├── 원천현황.md · 타임라인.md · 인물.md · 주의메모.md   1층 — 고정 파일명, 제자리 갱신
├── {산출물}_{YYYYMMDD}[_rN].md                        2층 — 스냅샷(같은 날 다시 만들면 _rN)
└── _작업/   사건세트.json · 색인.jsonl · 구간.jsonl · 증거목록_{ID}.jsonl · 배정_{ID}.jsonl · 전수성.json · 카드/
```

- 2층 파일명에 사건번호·인명을 넣지 않는다. 매니페스트의 경로는 모두 작업 루트 기준 상대 경로다.
- 2층 산출물의 front-matter(drafting 인계 계약)는 `references/05` §1.
- 카드는 파일 단위로 한 번에 쓴다. 동기화 폴더에서 생긴 충돌 사본은 `gate --out`이 알린다.

## 8. scripts

`scripts/evidence.py`(표준 라이브러리만, `--help` 한글). 종료코드 3은 검증 실패다. 항상 `python3`로, 작업 루트에서 절대경로로 실행한다. 스킬 기준 경로가 셸에서 보이지 않으면(Cowork 등 샌드박스 VM — 기준 경로는 호스트 경로이고 플러그인은 VM의 `$HOME` 아래에 마운트된다) 첫 명령에서 찾고, 출력된 절대경로를 이후 명령과 서브에이전트 브리프에 그대로 쓴다(셸 변수는 호출 사이에 유지되지 않을 수 있다). 경로가 셸에서 보이지 않는 것은 python이 없는 것이 아니다 — `python3` 자체가 없는 환경에서만 절차를 수동으로 한다(완성 게이트 미통과 — §2 완료의 모양):

```bash
E=$(find "$HOME" -maxdepth 8 -path '*/ko-evidence-analysis/scripts/evidence.py' 2>/dev/null | head -1); echo "$E"; python3 "$E" discover --root .
```

| 서브커맨드 | 용도 |
|---|---|
| `discover` | 서명으로 변환본 발견 |
| `import` · `locate` | 반입 / 옮겨진 원본 재탐색(크기가 같은 후보만 해시) |
| `gate` | 규격 불변식·세대 판정·반입 검증 |
| `index` | 작업 색인·구간 재구성, `_index.md` 대조·비고 칸 |
| `evlist` · `assign` | 형사 증거목록 파서 / (권, 면수)로 쪽별 순번 배정 |
| `cardfill` · `cardsha` | 카드 front-matter의 기계 필드(`record_id`·`pdf`·`출처sha256`·`좌표`·`증거ID`·`표식`) 채움 — `출처sha256`은 없을 때만, 원문을 다시 확인한 카드는 `--resha` / 구간 sha256 계산 |
| `coverage` | 양방향 전수성 |
| `derive` | 카드 색인 절에서 `타임라인.md`·`인물.md` 작성(손본 파일은 보존) + 주의메모 후보 수집 |
| `profile` · `sum` | 대화 내보내기 프로필 / 표 열 합산(소계·합계 행 제외, `--check`로 소계 검산, 열·범위 여러 개를 한 번에) |
| `verify` | 직접 인용 역검증 + 요약 좌표의 실재 검사 + 미해결 표식 집계. 파일을 지정하지 않으면 분석 폴더의 전 카드·산출물 |

## 10. 흔한 함정과 회피법

- **1층에 평가 혼입**: "신빙성이 낮다", "위법수집으로 보인다"는 2층이다. 1층에서 발견한 중대한 형식 사실의 이상(공소시효·제소기간, 영장 기재와 집행의 불일치)은 카드가 아니라 `주의메모.md`에 좌표와 함께 적는다.
- **카드를 증거처럼 인용**: 2층 인용은 반드시 원문 쪽에서 다시 딴다.
- **면수만으로 매칭**: 별권은 면수가 1부터 다시 시작한다. 좌표는 항상 (권 식별자, 면수) 쌍이고 권 식별자는 문자열("본권", "제3권", "별권 5" — 비교할 때 공백은 무시한다)이다. 변환 폴더명의 `_1`·`_2`는 파일 순번이지 권이 아니다.
- **기록 면수와 문서 쪽수의 혼용**: `printed_page`의 뜻은 기록마다 다르다. 매니페스트에 적힌 뜻을 따른다.
- **증거목록 순번의 목록 미특정**: 병합·추가기소 목록은 번호를 다시 매긴다. 순번은 (목록 ID, 순번) 쌍으로만 쓴다.
- **보유 없음의 단정**: 목록에는 있고 기록에 없는 증거가 등사 제외인지 변환 누락인지는 기록만으로 알 수 없다.
- **가림 뒤 인물의 추정**: `[마스킹]`·`김○○` 뒤의 인물을 채우지 않고 인물 목록에서 병합하지 않는다.
- **표의 단순 합산**: 소계·합계 행이 표 안에 있다. `sum`을 쓴다.
- **한글 키워드 grep의 누락**: 변환본은 한자·오탈자·옛 표기를 원문대로 둔다.

## 11. 사용자와의 상호작용

- 1층은 묻지 않고 시작한다. 1층 중에 확인을 기다리는 것은 형사 경로 판정이 갈릴 때와 형사 경로의 권·`printed_page` 뜻뿐이고(§2·§5-3), 나머지 매니페스트 확인(분류·증거번호)은 송부 때 한 번에 받는다. 2층은 §6의 세 가지가 불명확할 때만 한두 개 질문으로 좁힌다.
- **송부 순서**(맨 앞부터): ① 【중대 지적】(`주의메모.md`에 있으면 — 공소시효·제소기간 등) ② 사용자에게서 받아야 할 것(매니페스트 확인 — 분류·증거번호·권, 2층 착수 게이트에서 가정한 것) ③ 산출물 경로 ④ 완성 여부 — 통과하지 못한 게이트와 남은 표식의 종류별 개수 ⑤ 추정으로 둔 것(문건 경계, 증거 단위 배정, 인물 병합, 파일명에서 읽은 호증 번호) 한두 줄. 후기는 짧게.
