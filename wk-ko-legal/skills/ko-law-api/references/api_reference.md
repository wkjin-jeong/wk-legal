# 국가법령정보 OPEN API 참조 (skill 내부 문서)

본 문서는 `scripts/law_api.py`가 호출하는 `law.go.kr/DRF` API의 파라미터·응답 필드·인코딩 규칙을 요약한다.
공식 가이드: https://open.law.go.kr/LSO/openApi/guideList.do

---

## 1. 베이스 URL과 target 매트릭스

| 베이스 URL | 용도 |
|---|---|
| `https://www.law.go.kr/DRF/lawSearch.do` | 목록 검색 |
| `https://www.law.go.kr/DRF/lawService.do` | 본문 조회 |

| target | 대상 | 검색 결과의 식별자 필드 | 본문 조회 시 보낼 파라미터 |
|---|---|---|---|
| `law` | 법령(법률·시행령·시행규칙·대통령령 등) | `법령일련번호` (=MST) / `법령ID`(6자리) | **`MST=<법령일련번호>`** |
| `admrul` | 행정규칙(고시·훈령·예규·감독규정·지침) | `행정규칙일련번호` (긴 숫자, 약 13자리) / `행정규칙ID`(짧은 숫자) | **`ID=<행정규칙일련번호>`** |
| `ordin` | 자치법규(조례·규칙) | `자치법규일련번호` (=MST) / `자치법규ID` | **`MST=<자치법규일련번호>`** ⚠ |
| `licbyl` | 법령 별표·서식 | (검색 결과의 다운로드 URL 사용) | 검색 전용 — 본문 API 없음 |
| `admbyl` | 행정규칙 별표·서식 | (검색 결과의 다운로드 URL 사용) | 검색 전용 — 본문 API 없음 |
| `ordinbyl` | 자치법규 별표·서식 | (검색 결과의 다운로드 URL 사용) | 검색 전용 — 본문 API 없음 |
| `expc` | 법령해석례 (법제처 유권해석) | `법령해석례일련번호` (예: 332741) | **`ID=<법령해석례일련번호>`** |
| `eflaw` | 현행법령(시행일) — 연혁 포함 버전 | `법령일련번호`(버전별 MST) / `법령ID` | 현행 시행본: **`ID=<법령ID>`** 또는 `LM=<정식명>` / 특정 버전: **`MST=` + `efYd=`** |
| `admrulOldAndNew` | 행정규칙 신구법비교 | `행정규칙일련번호` | **`ID=<행정규칙일련번호>`** (또는 `LID=<행정규칙ID>`) |

> **자치법규(`ordin`) 본문 호출은 `MST=` 파라미터를 사용**한다(`ID=`가 아님).
> 검색 결과의 `<자치법규상세링크>`가 `target=ordin&MST=...` 형태로 나오는 것에서 확인됨.

> `MST`(마스터번호)는 한 법령·자치법규의 **시점별 본문**을 가리키는 식별자다.
> 동일 법령이라도 개정 이력이 있으면 시점별로 서로 다른 MST가 부여된다.
> ⚠ **`target=law` 본문은 '현행법령(공포일)' 기준**이다(공식 가이드 명칭). 공포됐으나 아직 시행되지 않은 개정이 있으면
> 검색 행은 `시행 20251216 | 현행`인데 같은 MST의 본문은 `<시행일자>20261217`로 미시행 조문까지 담아 온다
> (전자금융거래법 MST 280277 실측. 일부 조항만 미시행이면 `<조문시행일자문자열>`에 `20270701:제32조의2제1항 단서…`처럼 표시 — 개인정보 보호법 283839).
> 시행 중인 본문은 **`target=eflaw`에 `ID=<법령ID>` 또는 `LM=<정식명>`**으로 받는다(공식 가이드: "ID로 검색하면 그 법령의 현행 법령 본문 조회"). 공포본에는 거꾸로 **뒤에 공포됐으나 먼저 시행된 개정이 빠진다** — 민사소송법 현행 버전 법률 제19516호(2023. 7. 11. 공포, 2025. 7. 12. 시행, MST 252393)의 `target=law` 본문에는 법률 제20003호(2024. 1. 16. 공포, 2025. 3. 1. 시행)가 신설한 제402조의2·제402조의3과 제400조 제3항이 없고 제421조는 개정 전 문언이다(eflaw 523개 조 대 law 521개 조, 2026-09-27 실측). 이 역전은 본문만으로 판별할 수 없으므로 law_api.py의 `get --target law`는 `--promulgated`가 없으면 **언제나** 시행일 기준 본문(eflaw)으로 바꿔 출력한다 — `--lm`·`--id`는 현행(`ID=<법령ID>`), `--mst`는 그 버전의 시행일 기준(`MST=` + `efYd=<본문 시행일자>`), 미시행 내용이 있으면 현행(`ID=`).

> 행정규칙 본문 조회 시 헷갈리지 말 것: `<행정규칙ID>`(예: 21828)가 아니라
> `<행정규칙일련번호>`(예: 2100000274812)를 `ID=` 파라미터에 넣어야 한다.

## 2. 공통 파라미터

| 파라미터 | 필수 | 의미 |
|---|---|---|
| `OC` | ✅ | 인증키(이메일 ID 형식, open.law.go.kr 신청). 환경변수 `LAW_GO_KR_OC`로 관리 권장. |
| `target` | ✅ | `law` / `admrul` / `ordin` 등 |
| `type` | ✅ | 응답 포맷: `XML`(권장) / `JSON` / `HTML` |

## 3. 검색 API (`lawSearch.do`) 파라미터

| 파라미터 | 의미 | 비고 |
|---|---|---|
| `query` | 검색어 | 법령명·규칙명·조례명 등 |
| `display` | 결과 개수 (최대 100 — 넘기면 서버는 100건씩 자르고 쪽도 100건 단위로 센다: licbyl `--display 150 --page 2` = 101~200번째, 2026-09-27 실측. 스크립트는 100으로 낮춰 요청) | target별 기본값: `law`/`admrul`/`expc`=20, `ordin`/`licbyl`/`admbyl`/`ordinbyl`=50 (분야 키워드로 결과가 흔히 수백~수만 건이라 첫 페이지를 넓게 봐야 함) |
| `page` | 페이지 번호 | 1부터 시작 |
| `search` | 검색범위 | 법령 등: `1`=법령명(기본), `2`=본문 / 별표(`licbyl`·`admbyl`·`ordinbyl`): `1`=별표명(기본), `2`=관련법령명(모법별 목록), `3`=본문(다른 법령의 별표도 섞인다 — licbyl '건축법' 456건, 2026-09-27 실측) |
| `org` | 소관부처 | 행정규칙·자치법규에서 유용 |
| `knd` | 종류 코드 | target별 의미 다름 |
| `efYd` | 시행일자 범위 | `YYYYMMDD~YYYYMMDD` |
| `ancYd` | 공포일자 범위 | `YYYYMMDD~YYYYMMDD` |
| `sort` | 정렬 | `lasc`/`ldes`(법령명), `dasc`/`ddes`(공포일), `ndes` 등 |

### 검색 응답 실제 구조 (라이브 호출로 검증됨)

> 스크립트 `search`의 화면 출력은 이 응답을 줄인 **표**다 — 머리 줄(키워드·totalCnt·page·다음 쪽 안내) + 열 이름이 아래 태그 이름인 행. 원시 XML은 `--raw`, `--save-to` 파일은 늘 원시 XML이다. 자치법규 별표 링크의 긴 `flNm` 파라미터는 표에서 뺀다(없어도 다운로드된다 — 2026-09-26 실측). 공포(발령)번호 열은 앞자리 0 없이 내고(06627 → 6627), 행정규칙 자리표시 번호는 `없음(원값 9999)`으로 낸다.

## 4. 본문 조회 API (`lawService.do`) 파라미터

| 파라미터 | 의미 | 비고 |
|---|---|---|
| `MST` | 법령 마스터번호 | 특정 버전 지정 — 현행 인용은 eflaw `ID`/`LM`, 과거 버전은 eflaw `MST`+`efYd` |
| `ID` | 법령ID/행정규칙ID/자치법규ID | target에 따라 의미 다름 |
| `LID` | 행정규칙ID(admrul) | 버전과 무관한 계통 식별자 |
| `LM` | 정식 법령명·규칙명 | 검색 없이 단발 호출. 약칭 불가('자본시장법' → 일치 없음), 띄어쓰기는 무관(실측) |
| `JO` | 조문번호 | law·eflaw만 지원. 6자리 zero-padding (예: 제2조 → `000200`, 제390조 → `039000`). admrul·ordin은 무시되고 전문이 온다 — law_api.py가 받은 뒤 해당 조를 발췌 |
| `efYd` | 시행일자 | `YYYYMMDD`. eflaw `MST=`와 함께만 — `ID=`와 함께 보내면 HTTP 500(실측) |
| `ancYd` | 공포일자 | 서버 미지원 — 무시하고 현행본을 준다(2026-09-26 실측). law_api.py `get --ancyd`는 exit 2 — 과거 본문은 get-asof |
| `LANG` | 언어 | 무시된다(`LANG=EN`에도 `<언어>한글`). 영문본은 `target=elaw` |

> **영문 번역본(`target=elaw`)**: `ID=<법령ID>` 또는 `LM=<한글 법령명>`으로 받는다(`MST`·`JO`는 받지 않는다 — JO를 보내도 전문). 응답은 `<Law><InfSection>`(`lsId`·`ancYd`·`ancNo`·`lsNmEng` — 번역 기준 공포일·번호)·`<JoSection><Jo>`(`joNo` 4자리·`joBrNo` 2자리·`joYn`(N이면 같은 번호에 붙은 편·장 제목)·`joTtl`·`joCts`)·`<ArSection>`(부칙)·`<BylSection>`이다. `LM`은 한글 법령명이 맞아도 '일치하는 영문법령이 없습니다'가 나오기도 한다(형법 — 법령ID 001692로는 조회됨, 2026-09-27 실측). 번역이 없는 법령ID는 HTTP 500이다. law_api.py `get --lang EN`은 target law·eflaw의 `--id`·`--lm`을 elaw로 바꿔 부르고(`--lm`이 안 맞으면 법령ID로 재조회), `--jo`는 로컬에서 `joNo`·`joBrNo`로 발췌하며, stderr에 'NOTE: 영문 번역본(참고용·법적 효력 없음) — 번역 기준 공포 … 현행 한글본과 다를 수 있음'을 낸다(형법 번역 기준 공포 20230808 — 현행 한글본보다 앞선다).

### 본문 응답 실제 구조 (라이브 호출로 검증됨)

> `get`·`get-asof`에 `--text`를 붙이면 아래 구조에서 기본정보 한 줄과 조문 텍스트(법령은 `조문여부=전문`인 편·장·절 제목과 `항내용`·`호내용`·`목내용`을 들여쓰기로, 행정규칙은 `<조문내용>`, 자치법규는 `<조내용>`)만 평문으로 낸다. 해석례 등 그 밖의 본문은 짧은 값은 `태그: 값`, 긴 값은 `[태그]` 단락으로 낸다. 부칙·별표·연락처는 빠지므로 필요하면 `--text` 없이 받는다. 부칙은 `--jo` 없이 받은 원시 응답에만 있다(형사소송법 MST 74887 `JO=024900` 응답 1,894자·부칙단위 0 — 현행 전문은 735KB·부칙단위 45) — 필요한 개정의 부칙만 보려면 `--addenda <공포번호>`(`<부칙단위>`의 `부칙공포번호`를 정수로 대조, `<부칙내용>` CDATA를 이어 붙여 평문으로). 별표는 `JO`를 주면 응답에 없다(`<별표단위>` 0개 — 외국환거래법 시행령 MST 256657 실측) — 별표 하나는 `--byl <번호>`로 받는다(`--jo`와 함께 못 씀). 기본정보 한 줄의 공포(발령)번호는 앞자리 0 없이 내고, 행정규칙 자리표시 발령번호(9999)는 뺀다.

## 5. 조문번호(`JO`) 인코딩 규칙

API는 조문번호를 **6자리 zero-padding 숫자**로 받는다.
일반적인 패턴은 다음과 같다.

| 표시 | JO 값 | 설명 |
|---|---|---|
| 제2조 | `000200` | 앞 4자리=조 번호, 뒤 2자리=가지조(없으면 00) |
| 제100조 | `010000` | |
| 제390조 | `039000` | |
| 제390조의2 | `039002` | 뒤 2자리에 가지조 번호 부여 |

`law_api.py`의 `--jo` 인자는 사용자가 다음 형태 중 어떤 것으로 입력해도 받아들이도록 처리한다.

- `390` (숫자만) → `039000`으로 자동 패딩
- `039000` (이미 6자리 형태) → 그대로 통과
- `제390조`·`제390조의2`·`390의2` (자연어) → `039000`·`039002`
- `제7조제1항`·`제3조제2항제1호가목` → 조까지만 쓴다(`000700`·`000300`) — 본문 조회 API의 JO는 조 단위(6자리)뿐이므로 항·호는 받은 본문에서 확인한다(스크립트가 알림). 항·호·목 단위 조회 API(`lawjosub`·`eflawjosub`)는 공식 가이드에 있으나 미통합
- `제1항`처럼 '조'가 없거나 `390-2`처럼 해석할 수 없는 입력은 다른 조를 조회하지 않도록 exit 2
- 예외: 행정규칙(admrul)은 편·장식 조문번호(`7-14`·`제7-14조`·`제7-14조의2`·`10-21의2`)도 받는다(금융 감독규정 — 외국환거래규정·금융투자업규정·은행업감독규정 등). law·eflaw·ordin의 `390-2`는 계속 exit 2

## 6. 자주 마주치는 응답 패턴과 대처

### (1) 검색 결과 0건
- 띄어쓰기·괄호·약칭을 바꿔가며 재시도.
- 행정규칙은 `--org`(소관부처)를 함께 지정하면 적중률이 올라간다.

### (2) 응답이 HTML(오류 페이지)로 옴
- (`--type HTML`로 요청한 경우는 정상 페이지와 구별할 수 없어 검사하지 않는다.)
- OC 인증키가 잘못되었거나 미발급 상태.
- 일일 호출 한도 초과.
- 파라미터 조합이 잘못됨(필수 키 누락 등).

### (3) 본문이 `JO` 단위로 안 잘림
- 행정규칙(admrul)·자치법규(ordin) 본문 API는 JO를 받지 않는다(보내도 전문). law_api.py는 `--jo`가 오면 받은 본문에서 해당 조만 발췌해 출력한다(admrul: `<조문내용>`의 첫머리 `제N조(의M)`, ordin: `<조 조문번호='NNNNGG'>`). 조 여럿이 `<조문내용>` 한 블록에 이어진 행정규칙(외국환거래규정 — 1블록 184,336자·줄머리 표제 207개, 2026-09-27 실측)은 줄머리 조문 표제(`제7-14조(`)와 편·장·절·관 제목 줄을 경계로 그 조의 구간만 잘라 낸다(`제7-14조`는 `제7-14조의2`를 잡지 않는다).

### (4) 시행 전 내용(미시행 조문)이 섞임
- 검색 결과에 `시행일자`가 미래인 항목(시행예정)이 함께 나올 수 있다. 그보다 위험한 것은 **`현행` 행의 MST로 받은 `target=law` 본문에 미시행 조문이 섞이는 경우**다(1장 주의 참조) — 검색 행의 시행일자만 보고서는 걸러지지 않는다.
- 판별: 본문 `<기본정보>`의 `<시행일자>` > 오늘, 또는 `<조문시행일자문자열>`에 오늘보다 뒤인 날짜. 공포·시행 순서 역전(뒤에 공포됐으나 먼저 시행된 개정이 공포본에서 빠지는 경우 — 1장 주의)은 이 판별로 잡히지 않는다.
- 현행 인용은 `target=eflaw`의 `ID=`/`LM=` 본문을 쓴다. law_api.py의 `get --target law`는 `--promulgated`가 없으면 판별과 관계없이 언제나 eflaw로 대체한다.
- 없는 식별자는 HTTP 200 + `<Law>일치하는 법령이 없습니다. …</Law>`(JSON `{"Law": "…"}`)로 온다 — law_api.py는 exit 2로 종료하고 캐시하지 않는다.
- 시행 예정 개정 본문을 인용해야 한다면 그 사실을 서면에 명시한다("○년 ○월 ○일 시행 예정 개정 ○○법").

## 6-A. 별표·서식 (licbyl / admbyl / ordinbyl)

별표(別表)·서식(書式)은 법령·행정규칙·자치법규의 본문 끝에 붙는 첨부 파일성 자료다.
일반적으로 PDF·HWP/HWPX·이미지 형태로 제공되며, 별도 별표 조회 API는 없고
현행 파일은 **검색 응답 안의 다운로드 URL을 따라가는 방식**으로 가져온다. 기준일 판본은 모법 본문의 `<별표단위>`에 있다(아래 (a), `get-asof --byl`).

### 검색 URL

| target | 검색 엔드포인트 | section(검색 범위) | 응답 루트 | 항목 element |
|---|---|---|---|---|
| `licbyl` | `https://www.law.go.kr/DRF/lawSearch.do?target=licbyl&...` | `bylNm` (별표명) | `<licBylSearch>` | `<licbyl>` |
| `admbyl` | `https://www.law.go.kr/DRF/lawSearch.do?target=admbyl&...` | `admBylNm` (행정규칙 별표명) | `<admRulBylSearch>` | `<admrulbyl>` ⚠ |
| `ordinbyl` | `https://www.law.go.kr/DRF/lawSearch.do?target=ordinbyl&...` | `ordinBylNm` (자치법규 별표명) | `<licBylSearch>` ⚠ (licbyl과 동일!) | `<ordinbyl>` |

검색 파라미터는 다른 target과 동일(`OC`, `query`, `display`, `page`, `type` 등).

### ⚠ 검색 동작에 관한 핵심 주의 (라이브 검증으로 발견)

**별표·서식 검색의 `query`는 "별표 자체의 이름"을 본다.** 모법(법령·행정규칙·자치법규)의 이름이 아니다.
- 기본 검색(`search=1`, 별표명)에서는 "건축법" 같은 모법명으로 검색하면 0건 (별표명에 "건축법"이라는 글자가 직접 들어간 경우만 매칭).
- 모법별 별표 목록은 `--search 2`(관련법령명 검색 — licbyl '건축법' 99건(시행규칙 83·시행령 16), admbyl '전자금융감독규정' 37건, 2026-09-27 실측)로 받는다.
- 별표 자체의 통칭(예: "안전점검 검사 결과", "위탁지정신청서") 또는 분야 키워드("옥외광고물") 단위로 검색.
- 모법 본문에서 별표를 보려면(기준일 판본의 별표 등) **(a) 모법(law·eflaw·admrul)을 먼저 검색·본문 조회(`JO` 없이) → 본문 응답의 `<별표>` 아래 `<별표단위>`를 보거나**, **(b) 본문 응답에서 별표 다운로드 URL이 함께 노출되는지 확인**한다. `<별표단위>`의 필드는 `별표번호`(4자리)·`별표가지번호`(2자리)·`별표구분`(법령 `별표`/`서식`, 행정규칙 `별표`/`별지`)·`별표제목`·`별표시행일자`(법령만)·`별표내용`·`별표서식파일링크`(법령은 `별표서식PDF파일링크`도)다. law_api.py는 `get`·`get-asof`의 `--byl <번호>`(`--byl-kind 별표|서식`)로 하나를 골라 평문으로 낸다. 자치법규 본문의 `<별표단위>`는 첨부 묶음(`별표첨부파일명`)뿐이고 `별표내용`이 비어 있다(가평군 옥외광고물 조례 실측).
- ⚠ **검색(licbyl·admbyl·ordinbyl)은 별표마다 현행 1행만 준다**(외국환거래법 시행령 과태료 부과기준 — 공포 20260428 현행 1건뿐, 2026-09 실측). 처분일·거래일 기준 별표는 그 버전 본문(`get-asof --byl`)으로 받는다.

### `query=*` 와일드카드 (전체 목록 받기)

라이브 검증에서 `query=*`로 전체 별표·서식 목록을 받을 수 있음이 확인됨.
licbyl `*` → totalCnt=39,465 / admbyl `*` → totalCnt=83,249 (페이지네이션 필수).

```bash
python3 scripts/law_api.py search --target licbyl --query "*" --display 100 --page 1
```

### ⚠ admbyl 응답의 특수 사항

행정규칙 별표·서식(admbyl)에는 다음과 같은 특이 사항이 있다.
- **`<별표명>`이 비어 있는 경우가 다수** (특히 대법원 가족관계등록예규·등기예규 등). 파일명이나 인용 시 `관련행정규칙명_별표<별표번호>` 형태로 폴백 명명한다(스크립트 `download` 명령은 자동 처리).
- **다운로드 링크(`<별표서식파일링크>`)가 없는 항목 존재**. 이 경우 별표가 본문에 포함된 형태이므로 별도 다운로드가 불가능. 스크립트는 해당 항목을 스킵하고 카운트만 보고한다.
- **`<별표서식PDF파일링크>`가 제공되지 않음** (licbyl에만 PDF 변환본 제공).

### 응답에서 다운로드 URL 식별 (우선순위)

응답 XML의 항목별 자식 태그 중 다음을 다운로드 링크로 사용한다 — **PDF 변환본 우선**.

| 우선순위 | 태그명 | 비고 |
|---|---|---|
| 1 (최우선) | `<별표서식PDF파일링크>` | licbyl에서만 제공. PDF로 변환된 사본 — 텍스트 추출에 가장 유리 |
| 2 | `<별표서식파일링크>` | 모든 byl target에서 제공. 원본 형식(보통 HWP, 일부 PDF·이미지) |
| 후보(보수적) | `<별표파일링크>`, `<별지파일링크>`, `<서식파일링크>` | 응답 변형 대비 |

스크립트의 `download` 명령은 위 우선순위를 자동 적용하며, `is_pdf` 플래그로 PDF 여부를 표시한다.
상대경로(`/LSW/...`, `/DRF/...`)는 자동으로 호스트(`https://www.law.go.kr`)를 붙여 절대화한다.
실제 응답에서 위에 없는 새 태그명을 발견하면 `BYL_LINK_TAG_HINTS_PDF` 또는 `BYL_LINK_TAG_HINTS_RAW`(scripts/law_api.py)에 추가한다.

### 별표 단건 상세 조회 (보너스)

응답에 포함된 `<별표자치법규상세링크>`(또는 유사 필드)는 다음 형식이다.
```
/DRF/lawService.do?OC=<oc>&target=ordinbyl&ID=<별표일련번호>&type=HTML
```
즉 별표 자체에 대한 상세 페이지 조회 API도 존재(target은 검색과 동일하지만 `lawService.do`에 `ID=<별표일련번호>`를 보냄).
필요 시 `--type HTML`로 호출하여 별표 본문 HTML을 받을 수 있다.

### 다운로드·텍스트 추출 흐름

```bash
# 1) 별표서식 목록 검색 + 응답 저장
python3 scripts/law_api.py search --target licbyl --query "건축법" --search 2 \
    --display 20 --save-to ./byl_search_licbyl.xml

# 2) 검색 응답에서 추출된 모든 다운로드 URL을 일괄 다운로드 (PDF는 텍스트 추출까지)
python3 scripts/law_api.py download --from-search-xml ./byl_search_licbyl.xml \
    --extract-text --limit 5

# 3) 단건 직접 다운로드
python3 scripts/law_api.py download --url "/DRF/...별표파일URL..." \
    --filename "건축법_별표1" --extract-text
```

> **실패 처리**: HTTP 오류, 0바이트 응답, `text/html` 응답, 본문 앞머리의 '파일이 없습니다'(없는 `flSeq`에도 서버는 HTTP 200으로 59B `<script>alert(' 파일이 없습니다. ');</script>`를 준다 — 2026-09-26 실측)는 저장하지 않고 `FAILED: <URL> (<사유>)`를 stderr에 낸다. `--url`은 exit 3, `--from-search-xml`은 끝에 'N건 중 M건 실패'를 내고 모두 실패면 exit 3, 일부 실패면 exit 1이다. 검색 XML이 0건이면 'ERROR: 검색 결과가 0건입니다 …(--search 2 안내)'로 exit 1이고, 항목은 있는데 링크 태그를 못 찾을 때만 `BYL_LINK_TAG_HINTS` 보강 경고를 낸다. 저장 폴더는 저장 직전에 만든다.
> **PDF 텍스트 추출**은 시스템에 `pdftotext`(poppler-utils)가 설치되어 있어야 한다.
> macOS: `brew install poppler` / Ubuntu: `apt install poppler-utils`.
> HWP/HWPX는 자동 텍스트 추출 미지원 — 파일만 저장하고 사용자에게 안내한다.

### 별표·서식 인용 시 유의

- 별표는 형식상 본문의 일부지만, 인용 시 **「○○법」 [별표 ○]** 표기를 사용한다.
- 서식은 **「○○법 시행규칙」 [별지 제○호서식]** 처럼 표기.
- 별표를 본문에 옮길 때는 표 구조가 깨지지 않게 가능한 한 PDF에서 추출한 텍스트 그대로 옮기고,
  표 형태가 중요하면 PDF 페이지 번호를 함께 명시("별표 1, 2면 표")한다.

## 6-B. 법령해석례 (expc)

법제처가 정부기관·지자체의 질의에 대해 회신한 **유권해석**. 법률 자문의견서 작성 시 권위 있는 보강 근거가 된다.

### 검색·본문 URL

| 용도 | 엔드포인트 | 응답 루트 |
|---|---|---|
| 목록 검색 | `https://www.law.go.kr/DRF/lawSearch.do?target=expc&...` | `<Expc>` |
| 본문 조회 | `https://www.law.go.kr/DRF/lawService.do?target=expc&ID=...` | `<ExpcService>` |

검색 `section`은 `itmNm` (안건명 기준).

## 6-C. 과거(연혁) 법령 (eflaw / ordin nw=2 / admrulOldAndNew) — 공식 가이드 + 라이브 검증

### 시행일 법령 (target=eflaw) — 법령의 시점별 버전

검색(`lawSearch.do?target=eflaw`) 주요 파라미터 (공식 가이드 기준):

| 파라미터 | 의미 | 비고 |
|---|---|---|
| `LID` | **법령ID 한정** | 해당 법령의 버전만 반환 — 부분일치 오염(예: "민법" → 난민법) 차단. 권장 |
| `nw` | 1 연혁 / 2 시행예정 / 3 현행 (콤마 조합) | 기본 전체. 본 skill 기본값 `1,3`(시행예정 배제) — get-asof는 기준일이 오늘 뒤면 `1,2,3` |
| `sort` | `efasc`/`efdes` 등 | 시행일자 정렬 |
| `efYd` | `YYYYMMDD~YYYYMMDD` | 시행일자 범위 압축 |

응답은 `<LawSearch>`/`<law>`로 현행 검색과 동일 구조이되 **같은 법령이 시행일자별 행으로 반복**된다(버전별 `법령일련번호`=MST, `현행연혁코드`, 공포일자·공포번호 포함). 동일 (시행일자, MST) 중복 행과 **동일 MST가 복수 시행일자로 나오는 경우**(조문별 시행일 차이)가 있으므로 dedupe 후 사용한다.

본문(`lawService.do?target=eflaw`):
- **`MST=` 사용 시 `efYd=`(그 버전의 시행일자)가 필수** (공식 가이드).
- **`ID=`(법령ID)·`LM=`(정식명)을 주면 현행 시행본**이 반환된다 — 현행 조문 인용의 정공법. 과거본 조회에는 쓸 수 없고, `ID=`에 `efYd=`를 함께 보내면 HTTP 500(실측)이라 law_api.py가 efYd를 뺀다.
- `JO`(조번호)·`chrClsCd`(010202 한글/010201 원문) 지원. 응답에는 조문시행일자문자열·부칙·별표내용/별표서식(PDF)파일링크·개정문내용·제개정이유내용이 포함되어 연혁 분석에 유용(`JO`를 주면 별표는 빠진다 — 기준일 별표는 `get-asof --byl`).
- 실측: 옛 MST는 `target=law`로도 공포일 기준 본문이 반환되나 공식 경로는 eflaw다. law_api.py의 `get --target law`는 `--promulgated`가 없으면 언제나 시행일 기준 본문으로 바꾼다(`--mst`면 그 버전의 시행일 기준, 미시행 내용이 남은 버전이면 현행 시행본). 특정 과거 버전은 `get --target eflaw --mst --efyd` 또는 `get-asof`로 받는다.

버전 선택 규칙(law_api.py `get-asof` 내장): (시행일자, MST) dedupe → **계통 확정**(아래) → **max{시행일자 ≤ 기준일}** → 그 버전의 시행일자를 efYd로 전달. 기준일 이전 버전 부재(제정 전) 시 오류 + 최초 시행일 안내 — 기준일 전에 공포된 자리표시 행이 있으면 제정 전이라 하지 않고 시행일 미상 판본으로 안내한다(경기도옥외광고물등관리조례 계통 2024478: 1991. 2. 7. 제2104호부터 6건 모두 시행일자 99991231). 연혁 검색의 `제개정구분명`이 폐지·타법폐지인 행은 폐지 판본이다(조문 없음) — 선택본이면 "⚠ 폐지본", 직후 버전이면 판례식 "…로 폐지되기 전의 것"(대법원 2018도1966), 현행 행이 없는 폐지 계통은 `--jo` 현행 대조를 하지 않는다(공공기관의 개인정보보호에 관한 법률 001358 실측). 판례식은 직후 버전이 다음 셋 중 하나면 "…로 개정되어 ○. ○. ○. 시행되기 전의 것"으로 출력한다 — (A) **같은 개정(공포일·공포번호 동일)의 나머지 시행분**(단계적 시행 — 민법 제20432호), (B) **선택본 전에 이미 일부 시행된 개정의 나머지 시행분**(계통에 시행일자 ≤ 선택본 시행일자이면서 공포일·공포번호가 직후 버전과 같은 행이 있음 — 주택임대차보호법 제19356호, 상법 제20991호), (C) **선택본보다 먼저 공포되고 뒤에 시행된 개정**(직후 버전 공포일자 < 선택본 공포일자, 또는 같은 날·같은 종류에서 번호가 작음 — 도로교통법 제20864호). 선택본보다 뒤에 공포된 개정은 "…로 개정되기 전의 것"이다. 자리표시 행(시행일자 99991231·공포일자 00000000 — 서울특별시 강남구 옥외광고물 조례 MST 915155 등 자치법규 연혁 검색에서 실측)은 선택·직후 개정·B·C 판정과 계통표(최신 시행일·명칭)에서 빼고(`versions` 표에는 "자리표시 — 선택 제외"), 숫자가 아닌 번호('2022-44')는 같은 날 번호 대소 비교를 하지 않는다. 공포(발령)번호는 앞자리 0 없이 적고(06627 → 제6627호), 행정규칙 자리표시 발령번호(9999 — 금융감독원세칙 실측)는 종류·번호 없이 "(2024. 9. 13. 개정되기 전의 것)"으로 적는다(법령의 9999는 실제 번호라 유지).

조문 단위 대조(target=law·`--jo`·연혁본): 선택본 조문을 현행 조문(`ID=<법령ID>&JO=`, 1회)과 대조한다 — 조문단위(`조문여부=조문`)의 조문·항·호·목 내용에서 연도가 든 개정 표지(`<개정 …>`·`[본조신설 …]`)와 공백을 빼고 비교. 같으면 "통상 표기 가능" 안내, 다르면 선택본 뒤 버전을 시행일 오름차순으로 걸으며(같은 시행일 여러 행은 MST 최대 행 기준) 조문이 처음 달라진 버전을 찾아 "조문 기준 판례식"(통상형, 공포·시행이 어긋나면 시행형 병기)을 낸다 — 형법 제347조 기준일 20240410: 법령 기준 제20795호, 조문 기준 제21231호(2025. 12. 23.), 도로교통법 제148조의2 기준일 20190901: 조문 기준 제17371호(대법원 2022도3929의 특정과 같다). 상한 `--max-steps`(기본 10, 단계당 1회·캐시), 순차 탐색(바뀌었다 되돌아온 경우 대비). 연혁본이면 "경과조치 확인" 줄로 그 개정(또는 직후 개정)의 부칙을 받을 `--addenda` 명령을 안내한다.

계통 확정: 검색은 부분일치라 다른 규정·조례가 섞인다("전자금융감독규정" → 시행세칙, "가평군 옥외광고물" → 발전기금 조례). 섞인 채 고르면 **다른 규정의 본문·시행기간·판례식**이 나온다(2026-09-25 점검 재현). 검색 행의 `법령ID`·`행정규칙ID`·`자치법규ID`는 개정·개명과 무관하게 버전 사이에서 고정되므로 이를 계통으로 쓴다 — ① `--lid <계통ID>` ② 계통이 하나 ③ 어느 버전 명칭이 `--query`와 정확히 같은 계통이 하나 → 자동 선택, 그 밖에는 계통 목록을 보여주고 exit 2.

> `target=lsHistory`는 존재하지 않는다(라이브 검증 — HTML 오류 페이지).
> 법령 신구법 비교(`target=oldAndNew`, 구조문목록/신조문목록/신구법존재여부)는 공식 가이드가 확보되어 있으나 본 skill에는 미통합(2단계 후보).

### 자치법규 연혁 (target=ordin, nw)

- 검색 파라미터 `nw`: **1 현행(기본) / 2 연혁**. v1.1.0까지의 "자치법규 연혁 미지원" 기재는 nw 미지정 실측에 따른 오류였다.
- 연혁 행의 `자치법규일련번호`로 기존 본문 조회(`lawService.do?target=ordin&MST=`)가 그대로 동작(라이브 검증 — 2006년 시행본 회수).
- `org`(시·도)·`sborg`(시·군·구, org 필수 동반)·`knd`(30001 조례/30002 규칙 등)로 동명 조례를 구분.
- ⚠ 조례는 개정 시 명칭 변경이 잦다 — 정확명 필터로 거르면 옛 버전이 누락되므로 law_api.py는 ordin에 정확명 필터를 걸지 않고 명칭을 그대로 노출한다.

### 행정규칙 연혁 (target=admrul, nw) / 신구법비교 (admrulOldAndNew)

- **행정규칙 목록 조회도 `nw` 파라미터를 지원한다**: 1 현행(기본) / 2 연혁 (공식 가이드. v1.2.0의 "행정규칙은 연혁 검색 API가 없다" 기재는 nw 미지정 실측에 따른 오류 — 자치법규와 동일 패턴이었다). 보조 파라미터: `knd`(1훈령/2예규/3고시/4공고/5지침/6기타), `date`(발령일자), `prmlYd`(발령일자 기간), `modYd`(수정일자 기간), `sort=efasc/efdes`. 응답 항목은 `<admrul>` element이며 `<현행연혁구분>` 필드로 현행/연혁을 구분한다.
- 연혁 행의 `행정규칙일련번호`로 기존 본문 조회(`lawService.do?target=admrul&ID=`)가 그대로 동작한다(라이브 검증 — 현행여부 N 전문 회수). 본문 응답에는 부칙·별표(`별표서식파일링크`·`별표서식PDF파일링크`)·`첨부파일링크` 필드도 정의되어 있다(공식 가이드). 연혁 본문의 `<별표단위>`에 별표 본문이 들어 있어 `get-asof --target admrul … --byl <번호>`로 기준일 별표를 받는다(전자금융감독규정 20241225 — 별표 10건·별지 7건, `별표시행일자` 없음, 2026-09-27 실측).
- law_api.py `versions/get-asof --target admrul`은 `--query`(현행+nw=2 병합 검색, **기본·권장**) 또는 `--id`(체인 역추적, 보조)를 받는다.
- 신구법비교(admrulOldAndNew): 목록 `lawSearch.do?...&query=`(현행 단위), 본문 `lawService.do?...&ID=<행정규칙일련번호>` → `<구조문_기본정보>`/`<신조문_기본정보>` + 구조문목록/신조문목록(`신구법존재여부=N`이면 대비 없음).
- **체인 역추적(보조, 라이브 검증)**: `<구조문_기본정보>`의 일련번호(직전 버전)로 ① admrul 과거 전문 조회 ② admrulOldAndNew 재호출이 모두 가능 — 연혁 검색 교차 검증·조문 대비용(기본 상한 15단계, 단계당 API 1회).

### 법령
```bash

# 법률/시행령/시행규칙이 함께 검색됨 — 이름으로 구분해 법령ID 확보
python3 scripts/law_api.py search --target law --query "전자금융거래법" --display 10

# 법령ID로 현행 시행본(전문 또는 조문)
python3 scripts/law_api.py get --target eflaw --id <법령ID> --jo 9 --text

# 공포일 기준 본문(공포본)이 필요할 때만 — 미시행 조문이 섞이거나 뒤에 공포·먼저 시행된 개정이 빠질 수 있다
# (--promulgated 없는 get --target law는 언제나 시행일 기준 본문으로 바뀐다)
python3 scripts/law_api.py get --target law --mst <법령일련번호> --promulgated --text
```

### 행정규칙
```bash
python3 scripts/law_api.py search --target admrul --query "전자금융감독규정" --org 1160100   # org는 소관부처 코드(기관명은 exit 2)
python3 scripts/law_api.py get --target admrul --id <행정규칙일련번호> --jo 7 --text                 # 제7조만 발췌
```

### 자치법규
```bash
python3 scripts/law_api.py search --target ordin --query "옥외광고물" --org 6110000        # 서울특별시 코드(기관명은 exit 2)
python3 scripts/law_api.py get --target ordin --mst <자치법규일련번호> --jo 2 --text
```

### 과거(연혁) 법령
```bash
# 버전 목록 (법령ID 한정)
python3 scripts/law_api.py versions --lid 010513

# 기준일 시행본 + 조문 (선택 헤더는 stderr)
python3 scripts/law_api.py get-asof --lid 010513 --date 20190601 --jo 46 --text

# 기준일 뒤 개정의 경과조치(부칙) — get-asof 헤더 "경과조치 확인" 줄의 직후(또는 조문을 바꾼) 개정 MST·시행일·공포번호
python3 scripts/law_api.py get --target eflaw --mst <직후 MST> --efyd <시행일> --addenda <공포번호>
python3 scripts/law_api.py get-asof --lid 001671 --date 20150730 --addenda          # 기준일 뒤 개정 부칙 전부(--jo와 함께 못 씀)

# 기준일 별표 — 그 버전 본문의 <별표단위>에서 하나(--jo와 함께 못 씀, 서식은 --byl-kind 서식)
python3 scripts/law_api.py get-asof --lid 004273 --date 20250801 --byl 4

# 자치법규 연혁 — 검색어가 여러 조례에 걸리면 계통 목록이 나오고 --lid로 고른다
python3 scripts/law_api.py get-asof --target ordin --query "가평군 옥외광고물" --lid 2019869 --date 20150101 --text

# 행정규칙 연혁 — 정식 명칭이면 계통 자동 선택
python3 scripts/law_api.py get-asof --target admrul --query "전자금융감독규정" --date 20241225 --jo 7 --text
```

### URL만 확인 (실제 호출 없음, OC는 ***로 가림)
```bash
python3 scripts/law_api.py --dry-run search --target law --query "민법"
python3 scripts/law_api.py --dry-run get --target eflaw --lm "민법" --jo 390
python3 scripts/law_api.py --dry-run get-asof --lid 010199 --date 20150101 --jo 9   # 버전 검색 URL만(본문 URL은 선택 뒤 정해진다)
python3 scripts/law_api.py --dry-run download --url "/LSW/flDownload.do?flSeq=…" --out-dir <작업 폴더>/byl   # URL·저장 예정 경로만, 폴더 안 만듦
```
get-asof의 dry-run은 버전 검색 URL만 낸다(law는 eflaw 검색, ordin·admrul `--query`는 현행·연혁(nw=2) 두 URL, admrul `--id`는 admrulOldAndNew). download의 dry-run은 `--from-search-xml`이면 로컬 XML에서 뽑은 URL과 저장 예정 경로 목록(`--limit` 적용)을 낸다.

## 8. 보안 주의

- OC 값은 **사용자 식별자**다. 코드·로그·서면에 평문으로 노출하지 않는다.
- law.go.kr는 검색 응답의 상세링크마다 요청 OC를 그대로 echo한다. law_api.py는 stdout·`--save-to` 파일·캐시·`--dry-run` URL에서 OC를 가린다.
- 키는 파일(`.law_api.env` 또는 `~/.config/korean-law-api/.env`)로 두고, `--oc`·`LAW_GO_KR_OC=…` 명령줄 지정·`cat`/`echo`로 드러내지 않는다 — 에이전트 세션 기록에 평문으로 남는다(2026-09-25 점검: Cowork 기록 121개 파일에서 확인).
- API URL은 OC를 포함하므로(`?OC=...`), URL 자체를 외부에 공유하지 않는다.
