# 별표·서식·법령해석례 레시피

SKILL.md 7장에서 별표·서식이나 법령해석례가 필요할 때 읽는다. 명령은 스킬 폴더 기준이다(`scripts/law_api.py`).

## 기준일 별표 — 처분일·거래일에 시행 중이던 별표

별표 검색(licbyl·admbyl·ordinbyl)은 별표마다 **현행 1행만** 준다(외국환거래법 시행령 과태료 부과기준 — 공포 20260428 현행 1건뿐, 2026-09 실측). 아래 검색·다운로드 경로로 받은 파일을 처분시·거래시 별표로 인용하지 않는다 — 개정으로 기준이 달라진 경우가 있다(식품위생법 시행규칙 [별표 23] 행정처분 기준).

기준일 판본의 별표는 그 버전 본문의 `<별표단위>`에 있다. `get-asof`에 `--byl <번호>`를 준다.

```bash
# 법령(시행령·시행규칙) — 머리 한 줄([별표 N] 제목 · 별표시행일자 · 파일 링크) + 별표 본문
python3 scripts/law_api.py get-asof --lid <법령ID> --date <기준일> --byl 23
python3 scripts/law_api.py get-asof --lid <법령ID> --date <기준일> --byl 4의2
python3 scripts/law_api.py get-asof --lid <법령ID> --date <기준일> --byl 72 --byl-kind 서식   # 별지 제72호서식
# 행정규칙 — 별표·별지(별표시행일자 없음)
python3 scripts/law_api.py get-asof --target admrul --query "<정식 규정명>" --date <기준일> --byl 1
# 버전을 이미 안다면
python3 scripts/law_api.py get --target eflaw --mst <버전 MST> --efyd <그 버전 시행일자> --byl 23
```

- `--jo`와 함께 쓰지 못한다 — 조문을 지정하면 응답에 별표가 빠진다.
- 없는 번호면 그 버전의 별표 목록(번호·제목)을 보이고 exit 2로 끝난다. 목록에서 번호를 골라 다시 실행한다.
- 인용할 때는 선택본(stderr 헤더)과 머리 한 줄의 `별표시행일자`를 함께 적는다. `별표시행일자`는 그 버전의 시행일로 모든 별표에 찍히므로 그 별표가 개정된 날이 아니다 — 별표 개정 여부는 본문 첫 줄의 `<개정 …>` 표지나 두 기준일 본문 대조로 판단한다. 표·서식 모양이 중요하면 머리 한 줄의 파일 링크를 `download --url`로 받는다.
- 스크립트를 쓸 수 없으면 `--jo`·`--text` 없이 `--save-to`로 원시 응답을 받아 `<별표단위>`의 `별표제목`·`별표시행일자`·`별표내용`을 확인한다.
- 자치법규 본문의 별표는 첨부 묶음뿐이고 본문이 비어 있다 — 아래 ordinbyl 검색 → download로 받는다.

## 별표·서식 검색 → 다운로드 → 텍스트 추출

별표·서식은 별도 조회 API가 없고, 현행 파일은 **검색 응답에 포함된 다운로드 URL**을 통해 가져온다(기준일 별표는 위 절).
표준 흐름은 "검색 응답 저장 → `download --from-search-xml`"이다.

> ⚠ **기본 검색(`--search 1`, 별표명)의 query는 "별표 자체의 이름"을 본다 — 모법명이 아니다.**
> 기본 검색에서는 "건축법", "전자금융감독규정" 같은 모법명으로 검색하면 0건이 나온다.
> 별표 자체의 통칭("안전점검 검사 결과", "위탁지정신청서") 또는 분야 키워드("옥외광고물")로 검색한다.
> 모법별 별표 목록은 `--search 2`(관련법령명 검색 — licbyl '건축법' 99건, admbyl '전자금융감독규정' 37건, 2026-09-27 실측)로 받는다.
> 모든 별표·서식을 받아 추후 필터링하려면 `--query "*"`로 wildcard 검색이 가능하지만 totalCnt가 매우 크므로(licbyl ~3.9만, admbyl ~8.3만) `--display`/`--page`로 페이지네이션 필수.

> 응답의 `<별표명>` CDATA에는 검색어 강조용 `<strong>` HTML 태그가 끼어 있을 수 있다.
> 또한 admbyl에서는 `<별표명>`이 비어 있는 경우가 다수 있다.
> 스크립트의 `download` 명령은 HTML 태그를 자동 제거하고, 빈 별표명에 대해 `관련규칙명_별표<별표번호>` 형태로 폴백 명명한다.

> **다운로드 우선순위**: licbyl에는 `<별표서식PDF파일링크>`(PDF 변환본)와 `<별표서식파일링크>`(원본·보통 HWP)가 함께 제공된다. 본 skill의 `download`는 PDF를 우선 선택해 텍스트 추출에 유리하게 동작한다.
> admbyl/ordinbyl은 PDF 변환본이 제공되지 않는 경우가 많아 HWP 원본으로 저장되며, 자동 텍스트 추출이 어려워 사용자에게 안내된다.
> 일부 admbyl 항목은 다운로드 링크 자체가 없다 — 이 경우 본문에 별표가 포함된 형태이므로 모(母) 행정규칙 본문(`get --target admrul`)에서 직접 확인한다.

```bash
# 1) 법령 별표·서식 목록 검색 (target=licbyl) → 응답 저장(파일은 원시 XML, 화면은 표 — 표의 파일링크 열은 download --url에 그대로 쓸 수 있다)
python3 scripts/law_api.py search --target licbyl --query "위탁지정신청서" \
    --display 20 --save-to <작업 폴더>/byl_search_licbyl.xml

# 2) 응답에서 다운로드 URL을 자동 추출 → 작업 폴더에 저장 + PDF는 텍스트 추출
python3 scripts/law_api.py download --from-search-xml <작업 폴더>/byl_search_licbyl.xml \
    --out-dir <작업 폴더>/byl_downloads --extract-text --limit 5

# 1') 모법별 목록 — 관련법령명 검색
python3 scripts/law_api.py search --target licbyl --query "건축법" --search 2 \
    --display 20 --save-to <작업 폴더>/byl_search_licbyl.xml

# 3) 단건 직접 다운로드 (URL을 직접 알 때)
python3 scripts/law_api.py download --url "/DRF/lawService.do?...별표파일URL..." \
    --filename "건축법_별표1" --extract-text
```

행정규칙 별표·서식은 `--target admbyl`, 자치법규는 `--target ordinbyl`을 사용한다.
응답의 다운로드 URL이 상대경로(`/DRF/...`)면 스크립트가 자동으로 `https://www.law.go.kr` 호스트를 붙여 절대화한다.
받지 못한 파일(HTTP 오류·0바이트·HTML 응답·'파일이 없습니다' 안내)은 저장하지 않고 `FAILED: <URL> (<사유>)`를 낸다 — `--url`은 exit 3, `--from-search-xml`은 'N건 중 M건 실패'와 함께 모두 실패면 exit 3·일부 실패면 exit 1. 검색 XML이 0건이면 '검색 결과가 0건입니다'(exit 1)이므로 검색어·`--search 2`를 고친다. `--dry-run download`는 URL과 저장 예정 경로만 보인다.

**전제**: PDF 텍스트 추출에는 `pdftotext`(poppler-utils)가 필요. 설치되어 있지 않으면 PDF 파일은 저장만 되고 텍스트는 추출되지 않는다.
HWP/HWPX는 자동 텍스트 추출이 어렵다 — 파일만 저장하고 사용자에게 안내한다.

### 별표·서식 인용 형식 (서면용)
- **○○법 [별표 ○]** — 별표 인용
- **○○법 시행규칙 [별지 제○호서식]** — 서식 인용 (법령명에 「」 없음 — SKILL.md 6.)
- 별표 내용을 본문에 옮길 때는 PDF에서 추출한 텍스트를 그대로 옮기되, 표 구조가 깨지지 않게 정리.
- 표가 복잡해 텍스트로 옮기기 곤란하면 **"[별표 1] 참조"** 식으로 첨부 안내만 한다.

## 법령해석례(법제처 유권해석) 검색·본문 조회

법령해석례는 법제처가 정부기관·지자체 질의에 회신한 **유권해석**으로, 자문의견서·민사 서면에서 법리 보강 근거로 자주 활용된다.
본문 응답이 `<질의요지>`/`<회답>`/`<이유>` 3단으로 구조화되어 있어 **그대로 인용에 활용**하기 좋다.

```bash
# 1) 안건명 키워드로 검색 (예: 임차인 관련)
python3 scripts/law_api.py search --target expc --query "임차" --display 20

# 2) 검색 결과의 <법령해석례일련번호>로 본문 조회
python3 scripts/law_api.py get --target expc --id 332741 --text
```

### 법령해석례 인용 형식 (서면용)
- 정식: **법제처 21-0624 회신(2021. 12. 7.)**
- 약식: **법제처 21-0624 해석례**
- 본문 인용 시 `<회답>`을 결론으로, `<이유>`의 결정적 단락을 발췌해 논거로 사용.

> 법령해석례는 행정청을 사실상 구속하지만 **법원을 구속하지는 않는다**.
> 의뢰인 입장과 일치하는 해석례는 강력한 보강 자료가 되며, 반대 해석이 있다면 반드시 함께 제시·반박한다.

### 본문 인용 시 정리해야 할 두 가지 패턴 (라이브 검증으로 확인)

- **인라인 각주**: `<이유>` 본문 안에 `1)1) "운용리스"란 일반적으로 ...`, `2)2) 대법원 2012. 1. 19. 선고 2008두8499 전원합의체 판결례 참조` 처럼 각주가 본문 흐름에 끼어 있다. 서면에 옮길 때는 본문 흐름을 매끄럽게 만들기 위해 해당 부분을 별도의 각주로 분리하거나 괄호처리(예: "(주: 운용리스란 ...)")로 정리한다. 본문에 그대로 남겨두면 의미 흐름이 끊긴다.
- **「관계 법령」 섹션**: `<이유>` 마지막에 종종 `<관계 법령> ○ 지방세법 제7조 ...` 같은 관련 조문이 인용되어 있다. 자문의견서에서 같은 조문을 별도로 인용했다면 **중복을 피해 해석례 본문에서는 「관계 법령」 부분을 제외**하고, 동일 조문이 없을 때만 그 부분도 함께 인용한다.
