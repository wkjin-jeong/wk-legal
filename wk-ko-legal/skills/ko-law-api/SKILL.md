# Korean Law API (국가법령정보 OPEN API)

대한민국 법제처 「국가법령정보 공동활용」 OPEN API(`law.go.kr/DRF`)를 호출하여
**법령·행정규칙·자치법규의 최신 본문/조문**을 직접 조회하는 skill.

법률 서면(소장·답변서·준비서면·자문의견서)에서 법령을 인용할 때 LLM의 기억에 의존하면
**조문 번호 오류·옛 조문 인용·존재하지 않는 조항 인용** 등 치명적 실수가 발생한다.
본 skill은 그러한 위험을 차단하기 위해 매번 공식 API에서 본문을 받아 인용하도록 한다.

---

## 1. 언제 이 skill을 사용하는가

다음 중 하나라도 해당하면 즉시 이 skill을 사용한다.

- 사용자가 특정 법령·조문을 검색·조회·인용해 달라고 직접 요청한 경우
  - 예) "민법 제390조 본문 보여줘", "전자금융거래법 시행령 검색", "○○구 조례 찾아줘"
- 한국 법률 서면 작성·검토 중 **법령 본문을 정확히 인용**할 필요가 발생한 경우
  - `ko-civil-litigation-drafting`, `ko-legal-advisory-drafting` 등이 활성화된 상태에서
    조문을 직접 인용해야 할 때 이 skill을 보조적으로 호출한다.
- 행정규칙(고시·훈령·예규·감독규정)이나 자치법규(조례·규칙)의 본문 확인이 필요한 경우.

법령을 **기억에 의존해 인용하지 말 것**. 조문 번호와 항·호 구조까지 본 API로 확인한 뒤 인용한다.

## 2. 사전 준비 — 실행 위치와 인증키(OC)

### 2.1 실행 위치

- 명령의 `scripts/law_api.py`는 이 스킬 폴더 기준 경로다. 항상 `python3`로 실행한다(`python`이 없는 환경이 있다).
- **작업(출력) 폴더에서 절대경로로 실행**하고 스킬 설치 폴더로 `cd`하지 않는다 — 키 파일 탐색과 저장 파일(`--save-to`, `download`)이 현재 폴더 기준이다.
- 스킬 기준 경로가 셸에서 보이지 않으면(Cowork 등 샌드박스 VM — 기준 경로는 호스트 경로이고 셸은 VM이며, 플러그인은 VM의 `$HOME` 아래에 마운트된다) 첫 명령에서 찾아, 출력된 절대경로를 이후 명령에 그대로 쓴다(셸 변수는 호출 사이에 유지되지 않을 수 있다):

```bash
S=$(find "$HOME" -maxdepth 8 -path '*/ko-law-api/scripts/law_api.py' 2>/dev/null | head -1); echo "$S"; python3 "$S" get --target eflaw --lm "민법" --jo 390
```

### 2.2 인증키(OC)

API 호출에는 OC(open.law.go.kr에서 발급한 ID)가 필수다. 스크립트가 다음 순서로 찾는다.

| 순위 | 출처 | 비고 |
|---|---|---|
| 1 | `--oc` 인자 | 최후 수단 — 명령 기록에 키가 남는다(스크립트가 경고) |
| 2 | 환경변수 `LAW_GO_KR_OC` | 셸 프로파일에 이미 등록된 경우 |
| 3 | **키 파일 자동 탐색 (권장)** | `LAW_GO_KR_OC=<id>` 한 줄. `$LAW_API_DOTENV` → 현재 폴더부터 상위로 올라가며 `.law_api.env` → `./.env` → `scripts/.env` → 스킬 폴더 `.env` → `~/.law_api.env` → `~/.config/korean-law-api/.env` 순. `LAW_GO_KR_OC`가 없는 파일은 건너뛴다 |

- **Cowork 등 샌드박스 VM에는 `~/.config`가 없다.** 마운트된 작업 폴더 최상위(예: 진행사건 폴더)에 `.law_api.env`를 한 번 두면 그 아래 어느 폴더에서 실행해도 찾는다. 스킬 설치 폴더는 읽기 전용이고 업데이트 때 바뀌므로 키를 두지 않는다.
- **키 값을 `--oc`, `LAW_GO_KR_OC=… python3 …`, `export`, `cat`, `echo`로 드러내지 않는다** — 세션 기록에 평문으로 남는다. 키 파일을 못 찾으면 스크립트가 배치 위치를 안내하며 종료하므로, 그 안내를 사용자에게 전하고 임의 값으로 호출하지 않는다.
- 파일 형식은 `.env.example` 참조(`LAW_GO_KR_OC=your_id`, `export`·따옴표·`#` 주석 허용). 권한은 `chmod 600`.

## 3. API 엔드포인트 요약

모든 호출은 두 개의 베이스 URL과 `target` 파라미터로 분기된다.

| 베이스 | 용도 | 호출 스크립트 |
|---|---|---|
| `https://www.law.go.kr/DRF/lawSearch.do` | 목록 검색 | `scripts/law_api.py search` |
| `https://www.law.go.kr/DRF/lawService.do` | 본문 조회 | `scripts/law_api.py get` |

| target | 의미 | 검색 결과 식별자 필드 | 본문 조회 시 보낼 파라미터 |
|---|---|---|---|
| `law` | 법령 — **공포일 기준** 본문(공포본 전용: 미시행 조문이 섞이거나 뒤에 공포됐으나 먼저 시행된 개정이 빠질 수 있다 → `get --target law`는 `--promulgated`가 없으면 시행일 기준 본문으로 바꿔 출력) | `<법령일련번호>`(버전) / `<법령ID>` | `--mst` / `--id` / `--lm` |
| `admrul` | 행정규칙(고시·훈령·예규·감독규정) | `<행정규칙일련번호>`(긴 숫자, 버전) / `<행정규칙ID>`(계통) | `--id <행정규칙일련번호>` |
| `ordin` | 자치법규(조례·규칙) | `<자치법규일련번호>`(버전) / `<자치법규ID>`(계통) | `--mst <자치법규일련번호>` ⚠ |
| `licbyl` | 법령 별표·서식 | (응답의 다운로드 URL) | 검색 전용 — `download` 명령 사용 |
| `admbyl` | 행정규칙 별표·서식 | (응답의 다운로드 URL) | 검색 전용 — `download` 명령 사용 |
| `ordinbyl` | 자치법규 별표·서식 | (응답의 다운로드 URL) | 검색 전용 — `download` 명령 사용 |
| `expc` | 법령해석례 (법제처 유권해석) | `<법령해석례일련번호>` (예: 332741) | `--id <법령해석례일련번호>` |
| `eflaw` | 법령 — **시행일 기준** 본문(현행 인용의 정공법) | `<법령ID>` / `<법령일련번호>`(버전) | 현행: `--lm <정식명>` 또는 `--id <법령ID>` / 과거 버전: `--mst <버전MST> --efyd <시행일자>` |
| `admrulOldAndNew` | 행정규칙 신구법비교 (체인 역추적의 관문) | `<행정규칙일련번호>` | `--id <행정규칙일련번호>` |

> 자치법규(`ordin`)는 본문 조회 시 **`--mst`(=MST=)** 를 쓴다. 행정규칙과 다르므로 주의.
> 행정규칙 본문은 짧은 `<행정규칙ID>`(예: 21828 — 버전과 무관한 계통 번호)가 아니라 긴 `<행정규칙일련번호>`를 `--id`에 넣는다.

응답 포맷은 `type=XML`(기본) / `JSON` / `HTML` 중 선택. 본 skill은 **XML을 기본**으로 사용한다.

**출력은 짧게 받는다**: `search`는 표로 출력한다(열 이름 = 응답 태그 이름, 모든 행이 빈 열은 생략 — 원시 XML은 `--raw`). `get`·`get-asof`는 `--text`를 붙여 기본정보 한 줄 + 조문 텍스트(편·장 제목·항·호·목 포함, 부칙·별표 제외)만 받는다 — 민법 제390조 원시 XML 993자 → 189자, 전자금융거래법 제9조 2,543자 → 956자, 법령 검색 5건 2,421자 → 533자(2026-09-26 실측). `--save-to` 파일은 언제나 원시 응답이다(`download --from-search-xml` 호환 — 행정규칙·자치법규 `--jo` 발췌도 저장본은 발췌 전 전문). 부칙·조문별 시행일자·연혁 별표 같은 원시 필드가 필요할 때만 `--text` 없이 받는다(별표 하나는 `--byl` — 7장). 부칙은 `--jo` 없이 받은 원시 응답에만 있다 — 필요한 개정의 부칙만 보려면 `--addenda <공포번호>`(5.1).
파라미터·필드 상세는 `references/api_reference.md` 참조.

## 4. 표준 사용 흐름 — 현행 조문

현행 조문은 **시행일 기준 본문(`target=eflaw`)**으로 인용한다. `target=law` 본문은 공포일 기준이라, 공포됐지만 아직 시행되지 않은 개정이 있으면 검색 결과는 '현행'인데 본문에는 미시행 조문이 섞인다(전자금융거래법 2026-09 실측). 공포본에는 뒤에 공포됐으나 먼저 시행된 개정도 빠진다 — 민사소송법 법률 제19516호 공포본에 법률 제20003호(2024. 1. 16. 공포, 2025. 3. 1. 시행)의 제402조의2 등이 없음(2026-09-27 실측). 그래서 스크립트는 `get --target law`를 언제나 시행일 기준 본문으로 바꿔 출력한다(`--lm`·`--id`는 현행, `--mst`는 그 버전의 시행일 기준. 미시행 내용이 있으면 stderr에 ⚠, 없으면 NOTE). 공포본이 필요할 때만 `--promulgated`.

### ① 정식 법령명을 알 때 — 1회 호출

```bash
python3 scripts/law_api.py get --target eflaw --lm "민법" --jo 390 --text
```

`--lm`은 정식 명칭만 받는다(띄어쓰기 무관). 약칭('자본시장법')·오기는 "조회 결과 없음"(exit 2)이 나오므로 ②로 간다.

### ② 명칭이 불확실할 때 — 검색으로 법령ID 확보

```bash
python3 scripts/law_api.py search --target law --query "전자금융거래법" --display 5
python3 scripts/law_api.py get --target eflaw --id <법령ID> --jo 9 --text
```

검색 결과의 `법령명한글`로 법률·시행령·시행규칙을 구분하고 `법령ID`를 쓴다(`법령일련번호`는 버전 번호). 부분일치 검색이라 '민법'에 난민법이 먼저 나올 수 있다.

`--display`를 생략하면 law·admrul·expc 20건, ordin·licbyl·admbyl·ordinbyl 50건이 기본이다(최대 100 — 넘기면 NOTE와 함께 100으로 요청한다). 표 머리 줄의 totalCnt가 표시 건수보다 크면 머리 줄이 안내하는 `--page`로 넘긴다(안내는 요청한 `--display` 기준이다 — 안내가 없거나 '마지막 쪽을 지났습니다'가 나오면 멈춘다).

### ③ 행정규칙·자치법규

```bash
python3 scripts/law_api.py search --target admrul --query "전자금융감독규정"
python3 scripts/law_api.py get --target admrul --id <행정규칙일련번호> --jo 7 --text
python3 scripts/law_api.py search --target ordin --query "가평군 옥외광고물"
python3 scripts/law_api.py get --target ordin --mst <자치법규일련번호> --jo 2 --text
```

두 API는 조문 지정을 지원하지 않아 전문(행정규칙은 18만 자에 이르기도 한다)이 온다. `--jo`를 주면 스크립트가 해당 조만 발췌해 출력한다. 검색은 부분일치이므로 명칭과 `현행연혁구분`을 확인해 행을 고른다. 소관부처·지자체로 좁히려면 `--org`에 **코드**(예: 금융위원회 1160100, 서울특별시 6110000 — 자치법규 시·군·구는 `--sborg`)를 준다 — 기관명은 exit 2로 거부한다(API가 기관명을 조용히 무시하기 때문).

### 조문번호와 결과

- `--jo`는 `390`, `제390조`, `제10조의2`처럼 조까지 쓴다(가지조는 '의'로, `제7조제1항`처럼 항·호를 붙이면 조 전체를 받는다). 행정규칙 편·장식 조문번호는 `7-14`·`제7-14조의2`로 쓴다(admrul 한정 — 외국환거래규정처럼 조 여럿이 한 블록인 본문도 그 조만 발췌한다). 6자리 인코딩과 4자리 재시도는 스크립트가 처리하고, XML 응답에서 끝내 조문이 없으면 exit 2로 알린다 — 조문번호를 추정해 바꾸지 않는다.
- `--text` 출력은 첫 줄이 기본정보(법령명·종류·법령ID(행정규칙은 일련번호·계통ID, 자치법규는 MST·계통ID)·시행일자·공포(발령)일자·번호), 그 아래가 조문이다. 원시 XML 구조(법령 `<법령>`·행정규칙 `<AdmRulService>`·자치법규 `<LawService>`)는 `references/api_reference.md` 4장.
- 영문 번역본은 `get --target eflaw --lm <법령명> --lang EN --jo <조> --text`로 받는다(target=elaw로 조회 — 참고용·법적 효력 없음, 번역 기준 공포일은 stderr NOTE, 일부 법령만). `get --ancyd`는 서버가 무시하므로 exit 2다 — 과거 본문은 5장 `get-asof`.
- 사용자에게는 인용에 필요한 최소 범위만 발췌해 보인다. 상세 구조는 `references/api_reference.md`.

## 5. 과거(연혁) 법령 조회 — 행위시·처분시 기준

행정사건은 원칙적으로 처분 당시, 형사사건은 행위 시(형법 제1조 제1항), 민사도 법률행위 당시의 법령이 기준이 되는 경우가 많다. 이때는 현행이 아니라 **기준일에 시행 중이던 버전**을 조회한다. 본 기능은 `versions`(버전 목록)·`get-asof`(기준일 시행본 일괄 조회) 두 명령으로 수행한다.

다만 공소시효 같은 절차 규정을 어느 판본으로 적용할지는 형법 제1조 제1항만으로 정해지지 않는다 — 먼저 개정 법률 부칙의 경과조치·적용례를 확인한다. 예: 형사소송법 제249조는 2007. 12. 21. 법률 제8730호 부칙 제3조에 따라 그 시행 전 범죄에 제2항을 포함한 종전 규정을 적용하고(대법원 2022. 8. 19. 선고 2020도1153 판결), 제253조의2는 2015. 7. 31. 법률 제13454호 부칙 제2조에 따라 그 시행 전 범죄로 공소시효가 완성되지 않은 것에도 적용한다. 공소시효를 정지·연장·배제하는 규정에 경과규정이 없으면 소급 적용 여부를 법적 안정성·신뢰보호원칙에 비추어 신중히 판단하고(대법원 2015. 5. 28. 선고 2015도1362, 2015전도19 판결), 범죄 후 법정형이 가벼워졌으면 신법의 법정형이 공소시효기간의 기준이다(형법 제1조 제2항, 대법원 2008. 12. 11. 선고 2008도4376 판결).

### 5.1 기준일 결정

- 제공된 자료(처분서·공소장·계약서·사실관계 메모 등)에서 기준일이 **명백히 드러나면**(처분서의 처분일자, 공소사실의 범행일시, 계약 체결일 등) 그 시점을 1차적으로 채택하되, **산출물에 기준일과 그 근거를 반드시 명시**한다(예: "기준일: 2019. 6. 1.(처분일)").
- 자료에서 기준일이 **불분명하거나 나타나 있지 않은 경우에만** 사용자에게 확인한다.
- 행위시법·처분시법의 선택, 부칙 경과규정·소급 적용 여부의 판단은 변호사의 몫이다. 본 skill은 "기준일에 시행 중이던 본문"을 기계적으로 제공할 뿐이며, 경과규정이 있을 수 있음을 결과와 함께 알린다 — 경과조치·적용례는 선택본이 아니라 기준일 뒤 개정(직후 개정 등)의 부칙에 있으므로 get-asof 헤더의 "경과조치 확인" 줄대로 `--addenda`로 받는다(`--jo`·`--text` 응답에는 부칙이 없다). `get-asof`에서 `--jo` 대신 `--addenda`(번호 없이)를 주면 기준일 뒤 개정의 부칙 전부를 현행 본문에서 뽑는다.
- 기준일 시행본에 없는 조문(기준일 뒤 신설)도 그 개정 부칙의 적용례에 따라 기준일 전의 행위·사건에 적용될 수 있다 — "조문을 찾지 못했습니다"로 끝내지 말고 신설한 개정의 부칙을 `--addenda`로 확인한다.

### 5.2 법령 (target=eflaw)

```bash
python3 scripts/law_api.py versions --lid <법령ID>                          # 버전 목록(연혁 포함, LID 한정)
python3 scripts/law_api.py get-asof --lid <법령ID> --date 20190601 --jo 46 --text  # 기준일 시행본+조문 일괄
python3 scripts/law_api.py get --target eflaw --mst <직후 MST> --efyd <그 시행일> --addenda <공포번호>  # 그 개정의 부칙
```

법령ID는 기존 `search --target law`로 확보한다(LID 한정이 부분일치 오염 — 예: "민법" 검색 시 난민법 — 을 차단). 단계별 전체 레시피는 `references/api_reference.md` 6-C·7장 참조.

- `get-asof` 선택 규칙: (시행일자, MST) 중복 제거 후 **max{시행일자 ≤ 기준일}**. 기준일 이전 버전이 없으면(제정 전) 오류와 함께 최초 시행일을 안내한다 — 기준일 전에 공포된 자리표시 행이 있으면 '제정 전'이 아니라 "시행일이 자리표시값이라 특정할 수 없습니다"와 그 공포 정보를 낸다(원문·자치법규 연혁으로 확인). `--date`는 `20190601`·`2019-06-01`·`'2019. 6. 1.'`을 받는다. 연혁 검색의 자리표시 행(시행일자 99991231·공포일자 00000000 — 주로 자치법규)은 선택·직후 개정 판정과 계통표에서 빼고 NOTE로 알린다(`versions` 표에는 "자리표시 — 선택 제외"로 표시).
- 선택 결과(시행일자·MST·현행/연혁, 직후 개정의 공포 정보·MST)는 **stderr 헤더**로 출력된다 — stdout은 응답 본문만. 연혁본이면 시행기간이 함께 출력된다. 선택본이 폐지 판본(제개정구분 폐지·타법폐지 — 조문이 비어 있음)이면 "⚠ 폐지본"과 폐지 전날 날짜를 알리고, 직후 버전이 폐지면 판례식은 "…로 폐지되기 전의 것"이다(대법원 2018도1966 — 구 공공기관의 개인정보보호에 관한 법률).
- 연혁본에 `--jo`를 주면 선택본 조문을 현행 조문과 대조한다(target=law만 — 행정규칙·자치법규, 현행본이 없는 폐지 계통은 대조하지 않는다). 같으면 "연혁본이지만 제N조 문언은 현행과 같습니다 — 통상 표기 가능", 다르면 "⚠ 연혁본 — 제N조 문언이 현행과 다릅니다 … 구법 표기 필수"와 함께 뒤 버전을 시행일 순으로 대조해 그 조문을 처음 바꾼 개정의 "조문 기준 판례식"을 낸다(상한 `--max-steps` 기본 10, 단계당 API 1회·캐시). 개정 표지(<개정 …>)·공백 차이는 무시한다.
- 수동 조회 시: `get --target eflaw --mst <버전MST> --efyd <그 버전 시행일자>`. `--id`/`--lm`은 현행 시행본을 주므로 과거 버전에는 쓰지 않는다.
- nw 필터 기본값 `1,3`(연혁+현행) — 시행예정본을 원천 배제. 단 get-asof는 기준일이 오늘 뒤면 `1,2,3`으로 검색해 그날 시행될 판본을 고르고 "⚠ 시행예정본" 안내를 낸다(인용 때 시행일을 밝힌다).

### 5.3 자치법규·행정규칙 — 계통 확정

```bash
python3 scripts/law_api.py versions --target ordin --query "가평군 옥외광고물"
python3 scripts/law_api.py get-asof --target ordin --query "가평군 옥외광고물" --lid 2019869 --date 20150101 --text
python3 scripts/law_api.py get-asof --target admrul --query "전자금융감독규정" --date 20241225 --jo 7 --text
```

- 검색이 부분일치라 다른 규정·조례가 섞인다("전자금융감독규정" → 시행세칙, "가평군 옥외광고물" → 발전기금 조례). 스크립트는 버전 사이에 고정된 **계통ID**(`행정규칙ID`·`자치법규ID`)로 한 계통만 남긴다: `--lid <계통ID>` → 계통이 하나 → 어느 버전 명칭이 `--query`와 정확히 같은 계통이 하나면 자동 선택. 그 밖에는 **계통 목록(옛 명칭 포함)을 보여주고 exit 2** — 목록에서 골라 `--lid`로 다시 실행한다.
- 조례는 개정으로 **명칭이 바뀌는 일이 잦다**. 계통ID로 묶으므로 옛 명칭 버전도 함께 잡히고, 인용에는 선택본의 명칭을 쓴다.
- 동명 조례 구분이 필요하면 `--org <시·도 코드> --sborg <시·군·구 코드>`로 지자체를 한정한다.
- 행정규칙 **보조 경로 — 신구법비교 체인 역추적**(`--query` 대신 `--id <현행 행정규칙일련번호>`): 단계당 API 1회, 기본 상한 15단계(`--max-steps` — 법령 조문 기준 판례식 탐색에서는 기본 10). 연혁 검색의 교차 검증용.
- 직전 개정 전후의 **조문 대비**는 `get --target admrulOldAndNew --id <일련번호>`(`신구법존재여부=N`이면 대비 데이터 없음).

### 5.4 구법 인용 표기 (서면용)

- 정식(판례식): **구 자본시장과 금융투자업에 관한 법률(2018. 12. 31. 법률 제16191호로 개정되기 전의 것) 제46조** — get-asof 헤더의 "판례식"은 법령 기준이라 괄호의 공포일자·번호가 **직후 버전의 공포 정보**다.
- 서면의 괄호는 **인용 조문을 바꾼 개정** 기준이다(판례 관행 — 대법원 2022. 7. 28. 선고 2022도3929 판결의 "구 도로교통법(2018. 12. 24. 법률 제16037호로 개정되고, 2020. 6. 9. 법률 제17371호로 개정되기 전의 것) 제148조의2 제1항"). `get-asof --jo`의 "조문 기준 판례식"(통상형)을 쓴다. 그 개정의 공포와 시행 시점이 어긋나면 다음 줄에 혼동 우려 시에만 쓰는 시행형을 덧붙인다.
- 공포번호는 앞자리 0 없이 적는다(API 원값 06627 → 법률 제6627호). 행정규칙 발령번호가 자리표시값(9999)이면 종류·번호 없이 "(2024. 9. 13. 개정되기 전의 것)"으로 적는다 — get-asof 헤더·`versions` 표·`search` 표·`--text` 머리행은 이미 정규화한다(원값은 `versions --json`·`search --raw`).
- 직후 버전의 공포와 시행 시점이 선택본과 어긋나면 get-asof는 "구 민법(2024. 9. 20. 법률 제20432호로 개정되어 2026. 1. 1. 시행되기 전의 것)" 형태(시행 기준)로 출력한다. 경우는 셋이다: ① 같은 개정의 나머지 시행분(단계적 시행) ② 선택본 전에 이미 일부 시행된 개정의 나머지 시행분(주택임대차보호법 제19356호 — 2023. 4. 18.·7. 19. 두 번 시행, 사이에 제19520호) ③ 선택본보다 먼저 공포되고 뒤에 시행된 개정(도로교통법 제20864호 — 2025. 4. 1. 공포, 2026. 4. 2. 시행). 선택본보다 뒤에 공포된 개정은 "…로 개정되기 전의 것"이다. 이 판별은 버전(법령 전체) 단위다 — 서면의 괄호는 drafting 스킬 문체 가이드의 조문 단위 규칙(인용 조문을 바꾼 개정 기준, 통상형 기본)을 따르고, 조문 기준 판례식이 그 출발점이다. 부칙의 시행일 규정을 확인하고 최종 표기는 변호사가 정한다.
- 약식: **(2018. 11. 1. 시행 구 자본시장법 제46조)**.
- 인용 조문의 문언이 현행과 다르면 구법 표기와 시행기간(해당 시행일 ~ 직후 버전 시행일 전일)을 함께 쓰고 현행본과 섞지 않는다. 문언이 같으면(get-asof가 "현행과 같습니다"로 알림) 서면 스킬의 문체 가이드에 따라 통상 표기할 수 있다.

### 5.5 신·구법 대비 (법령)

행위시·처분시 본문과 현행 본문을 대비하는 명령은 따로 없다 — 두 기준일의 조문을 각각 받아 대조한다.

```bash
python3 scripts/law_api.py versions --lid <법령ID>                                      # ① 개정 시점
python3 scripts/law_api.py get-asof --lid <법령ID> --date <행위일·처분일> --jo <조> --text  # ② 구법
python3 scripts/law_api.py get --target eflaw --id <법령ID> --jo <조> --text              # ③ 현행
```

- ②의 stderr 헤더가 현행 대조 결과와 "조문 기준 판례식"(5.4)을 준다. ③은 `get-asof --date <오늘>`과 같은 결과다(재판시·현재 기준).
- 형법 제1조 제2항처럼 개정 경계가 쟁점이면 그 개정의 시행일 전날과 당일로 get-asof를 두 번 받는다. 경과조치·적용례는 `--addenda`로 확인한다(5.1).
- 예: 형법 제347조 — 기준일 2025. 12. 22.은 "10년 이하의 징역 또는 2천만원 이하의 벌금", 현행은 "20년 이하의 징역 또는 5천만원 이하의 벌금"(2025. 12. 23. 법률 제21231호로 개정).
- 법령 신구법비교 API(`target=oldAndNew`)는 직전 개정 전후만 비교해 행위시↔현행 대비에 맞지 않고 이 스크립트에 통합되어 있지 않다(행정규칙의 직전 대비는 `admrulOldAndNew` — 5.3).

## 6. 인용·표기 규칙 (서면용)

서면·의견서의 법령 표기는 호출한 서면 skill의 문체·인용 가이드를 따른다(민사 06·행정 08·형사 08·자문 05 — 모두 아래 형식과 같다). 단독 조회 답변의 기본형도 같다.

- 법령명은 정식 명칭으로, 「」 없이 쓴다: **민법 제390조**, **○○법 시행령 제○조**, **식품위생법 시행규칙 [별표 23]**.
- 항·호: **제390조 제1항 제2호** (점·중점 사용 금지, 한자 "제" 반복)
- 단서: **제390조 단서**, 본문: **제390조 본문**
- 긴 법령은 첫 인용에 약칭을 정의한다: **자본시장과 금융투자업에 관한 법률(이하 '자본시장법'이라 합니다) 제○조**.

본문을 그대로 인용할 때는 **API에서 받은 텍스트를 글자 그대로** 옮긴다 — 원문 속 「」와 괄호 한자(예: 추심명령(推尋命令))도 그대로 둔다(`../../shared/기본-문체-규칙.md` 3.). 서식상 줄바꿈/들여쓰기는 서면 스타일에 맞게 다듬을 수 있다.
**조문 번호·항·호 번호는 절대 임의로 바꾸거나 추정해 채우지 않는다.**

## 7. 별표·서식·법령해석례

별표·서식은 별도 조회 API가 없다.

- **현행 별표 파일**: 검색 응답의 다운로드 링크로 받는다(`search --target licbyl|admbyl|ordinbyl --save-to <파일>` → `download --from-search-xml <파일>`, 검색어는 모법명이 아니라 별표 자체의 이름이고, 모법별 목록은 `--search 2`). 검색은 별표마다 **현행 1행만** 주므로 처분시·거래시 별표로 쓰지 않는다.
- **기준일(처분일·거래일) 별표**: 그 버전 본문의 `<별표단위>`에 있다 — `get-asof --lid <시행령·시행규칙 법령ID> --date <기준일> --byl <번호>`(예: `23`, `4의2`. 서식은 `--byl-kind 서식`, 행정규칙은 `--target admrul --query …`). 머리 한 줄(`[별표 N] 제목 · 별표시행일자 · 파일 링크`)과 별표 본문이 나오고, 없는 번호면 그 버전의 별표 목록과 exit 2. `--jo`와 함께 쓰지 못한다(조문을 지정하면 응답에 별표가 빠진다). 자치법규 본문의 별표는 첨부 묶음뿐이라 ordinbyl → download로 받는다.

법령해석례는 `search --target expc` → `get --target expc --id <법령해석례일련번호> --text`로 받는다. 검색어 요령·다운로드와 텍스트 추출·인용 형식은 `references/byl_expc.md`를 읽는다.

## 8. 오류 처리·주의사항

- **OC 누락 / 잘못된 OC**: OC가 없으면 안내와 함께 종료한다. OC가 잘못되면 API가 HTML 오류 페이지, `resultCode≠00`, 또는 resultCode 없는 사용자 검증 실패 봉투(`<Response><result>…</result><msg>…</msg></Response>`, JSON이면 `{"result","msg"}`)를 반환하는데, 스크립트가 셋 모두 감지해 "OC 미등록·한도 초과·파라미터 오류" 취지의 메시지와 함께 비정상 종료한다(더 이상 오류 페이지·오류 봉투를 본문으로 오인하지 않음).
- **검색 결과 0건**: 띄어쓰기·괄호·약칭을 바꿔가며 재시도한다(예: "전자금융거래법" / "전자금융거래법(약칭)").
- **조문·식별자 없음**: 없는 MST·ID·LM은 "조회 결과 없음", 없는 조문은 "조문을 찾지 못했습니다"로 exit 2가 난다(캐시하지 않음). eflaw JSON은 일치 없음을 HTML로 돌려주므로 스크립트가 XML로 한 번 재확인해 분류한다. 자치법규·해석례는 명칭(`--lm`) 조회를 API가 지원하지 않는다(exit 2 — search로 번호 확보). 식별자는 search로, 조문번호는 원문으로 다시 확인하고, 추정 인용하지 않는다.
- **HTML 응답으로 받고 싶을 때**: `--type HTML` 사용. 단, 인용·발췌는 XML이 안정적이고, HTML은 오류 페이지와 구별할 수 없어 잘못된 OC여도 그대로 출력되며(exit 0) 캐시하지 않는다. 미시행 조문 대체도 하지 않는다.
- **API 호출 횟수 제한**: 법제처 정책상 일일 한도가 있을 수 있다. 성공 응답은 로컬 캐시(아래)에 24시간 보관되어 같은 조회의 재호출을 자동으로 절약한다.
- **미시행 조문·공포본**: `get --target law`의 출력은 `--promulgated`가 없으면 언제나 시행일 기준 본문이다(미시행 내용이 있었으면 '⚠ 공포일 기준 본문에 아직 시행되지 않은 내용'). 시행 예정 조문이 필요하면 `--promulgated`로 받고, 서면에 시행 예정임을 적는다. "공포본에는 있으나 시행일 기준 본문에는 없는 조문"이면 뒤에 공포됐으나 먼저 시행된 개정으로 삭제·이동됐을 수 있다.
- **기준일이 제정 전**: get-asof가 오류와 함께 최초 시행일을 안내한다. 기준일·법령 특정을 재확인. "시행일이 자리표시값이라 특정할 수 없습니다"면 제정 전이 아니다 — 안내된 공포 정보로 원문·자치법규 연혁을 확인한다.
- **API가 응답하지 않거나 정확한 본문 확인이 불가능한 경우**: 임의로 추정 인용하지 말고 사용자에게 사실대로 알리고 확인을 요청한다.

### 응답 캐시 (TTL 24시간)

`search`·`get`·`versions`·`get-asof`의 API 응답을 로컬에 캐시해 세션·skill 간 중복 호출을 줄인다(파일 다운로드는 캐시 대상 아님).

- 기본 위치 `~/.cache/wk-legal/law-api/`, 환경변수 `WK_LEGAL_CACHE_DIR`로 재정의. 만료 파일은 하루 한 번 자동 정리한다. Cowork 등 세션마다 새로 뜨는 VM에서는 캐시가 세션을 넘지 못한다.
- TTL **24시간**(mtime 기준). 성공 응답만 저장한다. 캐시 키는 **OC를 제거한 요청 URL의 sha256**이다. law.go.kr가 응답 본문(검색 응답의 상세링크 등)에 echo하는 OC는 캐시·stdout·`--save-to` 파일에서 모두 `OC=MASKED`로 가리고, `--dry-run` URL은 `OC=***`로 출력한다.
- 적중 시 stderr에 `CACHE:` 한 줄이 표시된다. 항상 새로 받으려면 `--no-cache`.

## 9. 다른 skill과의 협업

본 skill은 단독으로도 쓰이지만, 다음 skill과 결합해 가장 큰 가치를 낸다.

- `ko-civil-litigation-drafting`: 소장·답변서·준비서면 작성 시 청구원인·법리 부분에서 법령 인용
- `ko-legal-advisory-drafting`: 자문의견서의 "관련 법령" 섹션 정확성 확보
- `lbox-case-search`·`bigcase-case-search`: 판례에서 인용된 법령을 본 skill로 본문 조회하여 교차 확인
- 행정·형사 서면: 처분 당시·행위 시 법령은 본 skill의 `versions`/`get-asof`로 기준일 시행본을 확보해 구법 표기로 인용(5장)

협업 흐름 예시:
1. 서면 skill이 활성화되어 청구원인을 작성 중
2. "민법 제390조"를 인용해야 하는 상황 도달
3. 본 skill의 `get --target eflaw --lm`(명칭 불확실하면 `search` → `--id`)으로 시행 중인 본문 확보
4. 서면에 인용 형식으로 삽입
