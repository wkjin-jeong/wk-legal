# lbox-commentary-search

lbox.kr 주석서·실무서 검색에서 사용자 질의와 관련된 주석서 섹션을 자동으로 검색하고, 본문을 조회하여 사용자 질의에 답하는 markdown 보고서를 생성합니다.

이 Skill은 `lbox-case-search`(판례 검색)의 자매 Skill이며, 같은 lbox.kr 개편판 Chrome 자동화 패턴을 따릅니다.

> lbox.kr 2026.6 개편판 기준입니다 — 검색은 홈 컴포저 "검색" 모드 → 작업(Task) → 결과 패널의 "주석·실무서" 탭, 법령은 이름·문서유형 필터로 좁히고, 본문은 `/book/{bookId}?tocId=…&nodeId=…&volumeHistoryId=…`(node-id 중복 제거는 보험, PDF형 실무서는 `?page=N`). 개편 전 방식(`/v2/search/commentary`, 숫자 `statute` 코드)은 쓰지 마세요.

## 사전 조건 및 환경 점검

lbox.kr 로그인 + 주석·실무서 **구독이 항상 활성**이라고 전제합니다(구독 확인 분기를 두지 않음). 환경 점검은 `lbox-case-search`와 동일합니다.

1. **Chrome MCP 도구**: 이름에 `claude-in-chrome`(호스트에 따라 `Claude_in_Chrome`)이 들어간 Claude in Chrome 도구(현재 `mcp__claude-in-chrome__*` — `navigate`, `javascript_tool`, `get_page_text`, `browser_batch`, `computer`, `read_page` 등). 컴포저 입력·모드 선택·탭 클릭에는 `computer`/`find`가 필요합니다. **`javascript_tool` 반환은 약 1,000자에서 잘리므로** 카드·본문 추출 결과는 `references/extraction.md` 0장의 반환 규약으로 받습니다(추출 JS가 결과를 페이지에 내놓고 → `get_page_text` → 복구 JS, 세 호출을 `browser_batch` 하나로).
2. **연결된 브라우저 확인**: `list_connected_browsers` → 여러 기기면 `select_browser(deviceId)`. 대화마다 `tabs_context_mcp{createIfEmpty:true}`로 전용 탭 확보.
3. **검색은 '작업(Task)'을 생성**합니다(새 lbox의 정상 동작, 등록 '사건'과 별개). 한 검색 세션은 가급적 하나의 작업에서 진행하세요(같은 작업에서 재검색하면 입력창의 직전 검색어와 결과 패널의 필터가 남습니다 — `references/extraction.md` 1-1).
4. **JS 사전 점검**: 첫 페이지에서 `document.title` 평가로 정상 응답 확인.

## 작업 흐름

### 1단계: 사용자 의도 파악

- **검색어 (필수)**: 핵심 법률 쟁점·키워드. 자연어 질의는 짧은 키워드로 정제(예: "양도금지 특약이 있는 채권을 양도하면 효력이 있는지" → "양도금지특약").
- **법령 한정 (선택, 권장)**: 사용자가 법령을 명시하면 그 **이름**으로 좁힙니다(민법·민사소송법·상법·형법 등). 개편 후에는 숫자 코드가 아니라 법령 이름 필터를 씁니다. 사용 가능한 법령 목록·문서유형·필터 적용법은 `references/filter-map.md`를 이 시점에 읽습니다.
- **문서유형 (선택)**: 주석서 / 실무서 / 전체. 명시되지 않으면 전체에서 검색하고, 카드의 `docType`(유형 표지 — 주황 = 실무서, 하늘 = 주석서, 2026-09-26 실측. PDF형은 docId `실무서_…`)으로 판별합니다. 표지가 없을 때만 도서명 규칙을 보조로 씁니다(`references/filter-map.md`). 유형을 반드시 한정해야 하면 결과 패널의 주석서/실무서 칩(라디오)을 씁니다.

질의가 모호하면 진행 전에 한 가지만 확인하세요.

### 2단계: 검색 실행 (컴포저 "검색" 모드 → 주석·실무서 탭)

1. `navigate` → `https://lbox.kr/`.
2. 컴포저 입력창에 검색어를 입력하고 **"검색"(돋보기) 모드**를 선택한 뒤 **제출(↑)**. (구체 조작은 `references/extraction.md` 1장. `lbox-case-search`와 동일. 작업 페이지에서 재제출할 때는 입력창을 비운 뒤 — `references/extraction.md` 1-1.)
3. `/task/{id}`로 이동하며 결과 패널이 열립니다(기본 **판례** 탭).
4. 결과 패널 상단 탭에서 **"주석·실무서" 탭**을 클릭해 주석서 결과로 전환합니다. 이 탭은 **패널 안의 `role="tab"` 버튼**이며, **좌측 내비게이션의 "주석·실무서" 링크(`/book/list`로 이동)와 다릅니다** — 좌측 링크를 누르면 검색 결과를 잃고 도서 목록으로 가버리니 주의하세요(셀렉터 구분법은 `references/extraction.md` 1장).

> **이동·추출은 batch 한 번에**: 클릭·`navigate` 직후 곧바로 JS를 실행하면 timeout이 날 수 있으므로, 같은 batch 안에서 `computer` `wait` 2~3초를 먼저 넣고 추출합니다(`references/extraction.md` 0장).

법령·문서유형으로 좁히려면: (ⓐ) 주석·실무서 탭의 유형 칩과 '법령별 도서목록' 모달을 사용하거나, (ⓑ) 결과 단계에서 유형은 **docType**, 법령은 **도서명·breadcrumb**으로 선별하거나, (ⓒ) `https://lbox.kr/book/list`(문서유형·법령 필터가 있는 도서 목록)에서 대상 도서를 먼저 확인합니다. 자세한 건 `references/filter-map.md`.

### 3단계: 카드 추출 및 페이지 순회

주석·실무서 결과 카드는 `a[data-track-props]`(JSON `documentType:"scholar"`)이며, `docId`·`rank`와 **href에 본문 식별자**(bookId·nodeId·tocId·volumeHistoryId)가 들어 있습니다. PDF형 실무서(예: 민사집행실무총서 — book 87·85·88)는 href가 `/book/{bookId}?query=…&page=N`이고 tocId·nodeId·volumeHistoryId가 없습니다(2026-09-26 실측, 카드 `bodyType` `pdf`). 카드 컨테이너(`div.border-b-xs`)의 3부분(① 섹션 제목+도서메타, ② 스니펫, ③ breadcrumb)과 식별자 분해, 중복 제거 JS는 `references/extraction.md` 1장을 따릅니다.

#### 페이지 순회 정책

- 결과는 10건/페이지, 하단 **번호 페이지네이션**(판례 탭과 동일 — 번호 5개씩 묶음이라 6페이지 이후는 ›로 묶음을 넘긴다. 이동 JS와 마지막 페이지 판정은 `references/extraction.md` 1-4). **최소 2페이지(상위 20건)** 까지 수집하되, 누적 **High 후보 ≥ 5건**이면 본문 visit로 진입.
- 결과가 매우 적으면(예: 5건 미만) 추가 페이지 없이 곧바로 본문 visit. **0건**이면 키워드를 넓히거나 법령 한정을 풀어(같은 작업이면 적용된 필터 칩을 초기화) 1차 재검색을 제안(진행 전 한 줄 안내).

### 4단계: 1차 관련성 분류 (snippet triage)

각 결과를 4개 신호로 분류합니다. (판례 검색과 동일한 정신.)

- **섹션 제목(`sectionTitle`)**: 질의 키워드 직접 포함 시 ↑.
- **스니펫(`snippet`)**: 질의 쟁점을 정면으로 다루면 High, 키워드만 있고 쟁점이 다르면 Low.
- **breadcrumb**: 도서 내 위치(예: "제3편 채권 / 제5장 불법행위"). 질의 분야 일치 시 ↑.
- **도서명(`book`)**: 권 단위 적합성(예: 채권양도 → "민법 채권총칙", 불법행위 손해 → "민법 채권각칙").

**참고문헌 모드 보정**: 스니펫이 논문·문헌 목록(`민사판례연구|민사법학|…연구\(\d{4}\)`, 따옴표 논문 제목+연도, 저자+책+출판사+연도 패턴이 2회 이상)으로 채워졌으면 스니펫 가중치를 낮추고 섹션 제목·breadcrumb·도서명에 비중을 둡니다. 이때는 스니펫만으로 Low 처리하지 말고 Medium으로 두어 본문 visit 후 재판단(false negative 회피).

본문 visit은 **High + Medium 후보만** 수행합니다.

### 5단계: 본문 visit 및 섹션 추출

각 후보의 식별자로 본문 URL을 구성해 `navigate`합니다.

```
https://lbox.kr/book/{bookId}?tocId={tocId}&nodeId={nodeId}&volumeHistoryId={volumeHistoryId}
```

PDF형 실무서(`bodyType` `pdf`)는 `https://lbox.kr/book/{bookId}?page={page}`입니다. 기본은 본문을 열지 않고 스니펫·page만 보고하며 `본문 미확인(PDF형 실무서)`로 표시합니다. 그 실무서가 핵심 쟁점의 유일한 근거일 때만 `references/extraction.md` 2-2 절차로 엽니다.

(카드 href를 그대로 navigate해도 됩니다 — 단 JS 결과에 raw href를 담아 반환하면 `[BLOCKED]`가 나므로, 식별자는 **분해된 필드로** 받아 URL을 구성합니다. `references/extraction.md` 1장.)

섹션 추출 메커니즘(URL의 `nodeId`에 해당하는 `[data-node-id]` 헤더부터 다음 `[data-viewer-type="header"]` 전까지 형제 수집, node-id 중복 제거(보험), 섹션이 큰 챕터일 수 있어 전문은 window 변수에 저장하고 **질의 키워드 인근 발췌**로 반환)은 `references/extraction.md` 2장을 이 시점에 읽고 그대로 사용합니다.

#### 5.1 본문이 빈약할 때 — 같은 조문/장의 하위 노드 추가

조문 본문 노드(`제449조 [채권의 양도성]` 등)는 조문 ①②③항 + 관련조문 + 참고문헌만 있어 빈약(노드 < 10개 또는 < 2,000자, 또는 조문 텍스트+`[참고문헌]`/`[관련조문]`뿐)할 수 있습니다. 핵심 법리(Ⅰ. 의의, Ⅱ. 성립요건 …)는 같은 조문/장의 하위 노드에 분산됩니다. 이 경우:

1. 같은 검색 결과에서 **같은 도서(`book`) + 같은 breadcrumb 부모**를 공유하는 다른 카드(같은 조문/장의 하위 노드)를 찾습니다.
2. 질의에 가장 가까운 1~2개를 추가로 본문 visit합니다.
3. 같은 결과에 적합한 하위 노드가 없으면 viewer의 도서 목차에서 인접 노드를 확인하거나 다른 출판사 주석서를 visit합니다.

조문 본문 노드만 보고 답변하면 "법리 설명 없음"의 빈약한 답변이 됩니다.

#### 5.2 본문 추출 실패 시

- `header not found`: JS가 함께 내는 진단값으로 원인을 가른다(`references/extraction.md` 2-1). `nodeCount` 0이면 로드 미완(`wait` 뒤 1회 retry) 또는 PDF형(`pdfViewer` true — retry하지 말고 2-2로). `viewerHeaders`가 있는데 대상만 없고 카드 스니펫이 섹션 제목 그대로면 절·장 제목 노드다 — retry하지 말고 같은 breadcrumb의 첫 하위 노드 카드로 가거나 `firstHeader`부터 읽는다. 그 밖에는 한 번 retry 후 실패면 그 카드 건너뜀.
- 섹션 길이 0 또는 200자 미만: retry 후에도 실패면 건너뜀(구독은 활성 전제이므로 구독 안내 표시 안 함).

#### 5.3 인용 조문·판례 재검증과 추가 단서

핵심 주석서 1~2개에 한해 인용 판례(`\d{4}[가-힣]+\d+`)·인용 조문(예: "민법 제449조")·인용 학설을 추가 추출해 "주석서가 인용한 핵심 판례·법령" 표에 정리하면 답변 품질이 올라갑니다.

주석서는 2차 문헌입니다. **"정리된 답변"이나 핵심 판례·법령 표에 옮기는 조문·판례는 재검증한 것만 단정합니다**(필수 — 2차 문헌 공통 원칙, `shared/기본-문체-규칙.md` 9.). 주석서에 인용된 조문·판례 번호를 재검증 없이 그대로 옮기지 않습니다.

1. **조문 — 판본 이후 개정 확인**: ko-law-api로 두 문언을 대조합니다. 판본 기준 문언은 `get-asof --query <법령명> --date <bookMeta의 출판일 YYYYMMDD> --jo <조> --text`, 현행 문언은 같은 명령에 `--date <오늘 YYYYMMDD>`로 받습니다(24시간 캐시). 두 문언이 다르면 판본 이후 개정입니다. 현행 문언만 볼 때는 그 조의 모든 항·호의 표지(`<개정 …>`는 항마다 붙고 한 표지에 날짜가 여럿 나열될 수 있음, `<신설 …>`·`[전문개정 …]`·`[본조신설 …]` 포함)에서 가장 늦은 날짜가 출판일보다 뒤인지로 판단합니다. 법령 전체의 `versions` 개정일이나 get-asof의 '직후 개정' 표시만으로 판단하지 않습니다 — 다른 조문 때문에 개정됐을 수 있습니다(예: 형법 2023. 8. 8. 법률 제19582호는 제347조와 무관).
2. **판례**: 판례DB(원격 MCP `read_case`, 로컬 `case_db.py read '<법원> <사건번호>'`)로 사건번호·선고일·판결 종류를 확인하고, 표기는 결과의 citation을 그대로 씁니다. 판례DB가 없거나 판례DB에 없는 사건이면 lbox-case-search의 사건번호 URL 직행으로 확인합니다(`shared/판례-인용-정책.md` 1.1-5).
3. **개정 표시**: 판본 이후 개정된 조문을 전제한 서술에는 `⚠ 판본(<출판일> <판>) 이후 개정: <법령> 제○조 — <현행 요지>(<공포일> 법률 제○호)`를 붙이고 현행 문언을 함께 적습니다(예: 형법 제347조 제1항 — 2022년 판본은 '10년 이하의 징역 또는 2천만원 이하의 벌금', 2025. 12. 23. 법률 제21231호로 '20년 이하의 징역 또는 5천만원 이하의 벌금').
4. **미검증 표시**: 재검증하지 못한 것과 답변·표에 옮기지 않은 나머지 인용은 `주석서 기재·미검증`으로 표시합니다.

### 6단계: 본문 기반 최종 관련성 분류

- **직접 관련(High)**: 질의 쟁점을 정면으로 다룬 섹션 → "정리된 답변"+"참고 주석서" 양쪽 사용.
- **간접 관련(Medium)**: 동일 분야 일반론·비교 가치 → "참고 주석서"에 한 줄 요지만.
- **관련성 낮음(Low)**: 키워드만 우연히 일치 → "제외 섹션" 목록에 메타데이터만.

판본 이후 개정된 조문을 전제한 High 섹션은 현행법과 구분해 서술합니다(5.3의 3.).

### 7단계: 결과 markdown 파일 작성

- **위치**: 사용자가 선택한 작업 폴더(없으면 outputs/ + `computer://` 안내). 절대 경로 하드코딩 금지.
- **파일명**: `lbox-commentary-<주요키워드>-<YYYYMMDD>.md`. 예) `lbox-commentary-양도금지특약-20260629.md`. 민감정보 제외.

보고서 표준 양식은 **`references/report-format.md`를 작성 직전에 읽고 그대로 따릅니다.**

#### 인용·발췌 가이드

lbox.kr은 구독자에게 본문 직접 인용을 허용합니다. 분량을 임의 제한하지 않되 가독성을 위해: **핵심 부분은 직접 인용(`"..."`)**, 그 외는 요약, **출처는 도서명과 위치로 인라인 인용하고 저자(편집대표)·판본은 "참고 주석서" 절에 표기**(예: `[김용덕 편, 민법 채권각칙 제6권, 제○조 해설 Ⅲ. 1.]` — 보고서용 형식이다. 서면에 옮길 때의 형식은 `references/report-format.md` 출처 표기 원칙), **본문에서 확인되지 않은 내용 금지**. 주석서가 인용한 조문·판례는 5.3으로 재검증한 뒤에만 단정합니다.

#### 파일 안내

저장 후 경로 안내: Cowork/데스크톱은 `computer://` 링크, CLI 등은 절대 경로 텍스트.

## 문제 발생 시

증상별 대응은 `references/troubleshooting.md` 참조. 핵심: ① 본문은 `data-node-id`/`data-viewer-type="header"` 형제 수집으로 읽고 이미 본 node-id는 건너뜀(중복 렌더 대비, PDF형 실무서는 `references/extraction.md` 2-2), ② `navigate`/클릭 뒤에는 batch 안에서 `computer` `wait`로 기다린 뒤 추출(`Runtime.evaluate timed out`이면 그 페이지만 분리 호출, `-32603 Internal error`면 JS가 약 40초를 넘은 것이니 JS 안 대기·순회를 줄임), ③ 결과 JSON에 raw URL·쿼리스트링·검색 키워드를 담지 말 것(`[BLOCKED]` 회피), ④ "주석·실무서"는 **패널 탭**을 누를 것(좌측 내비 링크 아님).
