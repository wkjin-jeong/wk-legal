# bigcase-case-search 보고서 양식 reference

보고서 작성 직전에 이 파일을 읽고 그대로 따른다.

다음 형식의 markdown 파일을 저장합니다.

```markdown
# 질의: <사용자의 원래 질문>

## 검색 조건

- 검색원: bigcase.ai(병합 보고서는 아래 "병합 보고서" 절)
- 검색어: <검색에 사용한 키워드(재검색 시 모두 나열)>
- 사건유형: <민사/형사/행정/헌법/특허/가사 또는 미지정>
- 법원: <대법원 또는 미지정>
- 재판유형: <판결/결정 또는 미지정>
- 선고기간: <최근 N년 또는 미지정>
- 검색일자: <YYYY-MM-DD>
- 검색결과: <총 N건 중 조회한 판례 M건 + 추가로 조회한 상급심·참조판례 K건 등>

## 정리된 답변

<사용자 질의에 대한 답변. 판례 내용을 종합한 설명을 자연스러운 문단으로 작성.
각 주장/진술 끝에 [대법원 2023다12345] 형식으로 출처 사건번호를 인라인 인용.
하나의 진술이 여러 판례로 뒷받침되면 [대법원 2023다12345; 2022다67890] 형식으로 묶어 표기.
결론을 가르는 사실관계 변수(통지 명의자, 대리권 위임 여부, 송달방식 등)를 명확히 구분해 정리.>

## 참고 판례

### [사건번호] 사건명

- **법원·선고일자·종류**: <예: 대법원 2023. 5. 8. 선고 / 판결(전원합의체 여부)>
- **판시사항**: <있으면 — 하급심 미공보 판례는 없을 수 있음>
- **재판요지**: <있으면>
- **관련 내용**: <사용자 질의와의 관련 부분 요약. 판시사항·재판요지가 없는 하급심은 이유에서 발췌 정리>
- **결론**: <원고승/패, 상급심 흐름 등>
- **원문**: https://bigcase.ai/cases/<법원명>/<사건번호>

### [사건번호] 사건명

...

## 참조 대법원 선례 정리 (있으면)

| 선례 | 법리 | 근거(참조판례로 인용된 판례·중요판례 표시 등) |
|---|---|---|
| 대법원 ... | ... | ... |

## 관련 문헌 (선택 — bigcase "관련 논문"에서 수집한 경우만)

- <논문 제목> (bigcase 관련 논문 목록 수집분 — 내용 미확인, 제목만 제공)
```

저장 후 사용자에게 결과 파일 경로를 안내합니다.

- **Cowork 등 데스크톱 환경**: `computer://` 링크 사용. 경로는 사용자의 실제 작업 폴더 절대 경로 + 위에서 정한 파일명을 조합.
  - 형식: `[검색 결과 보기](computer://<사용자의 작업 폴더 절대 경로>/<파일명>)`
- **그 외 환경(CLI·웹 등)**: 절대 경로 텍스트로 안내하거나 환경이 지원하는 파일 링크 형식을 사용.

**경로 하드코딩 금지**: 작업 폴더 경로는 사용자 환경마다 다릅니다. 매 답변마다 실제 작업 폴더 경로를 사용하세요.

#### 답변 형식 보강 권장사항

- 결론을 가르는 **사실관계 변수**를 식별하고, 답변에서 이 변수에 따라 결과가 어떻게 달라지는지 정리하세요.
- 참고 판례 표기 시 결과(원고승/패)와 패소 사유가 본 쟁점인지 별도 사유인지를 구분해 적으세요.
- **상급심 흐름 표기**: 하급심 판례를 인용할 때 상급심이 있으면 **결론** 항목에 진행 흐름을 명시합니다. 예: "원고일부승(1심) → 파기환송(대법원 ○○다○○○○) → 항소기각(환송 후 2심)". bigcase 상하급심 체인에는 관계 라벨이 없으므로 이 흐름은 **각 본문의 주문에서 확인한 것만** 적습니다. 상급심 본문을 어디서도 열 수 없어 lbox 라벨로만 결론을 확인한 경우(SKILL 4.5단계 (가) ⑤)는 "제1심 → 항소기각(대전지방법원 2020노3896 — 본문 미확인, lbox 라벨로만 확인)"처럼 적고 말미 "검토 한계"에도 올립니다. 상급심이 결론을 뒤집은 경우 본문 인용은 상급심 결론을 우선 반영하고 하급심은 "원심/환송 전 판결"로 표기.
- bigcase 카드에는 인용 수가 없으므로, 선례 안정성 근거로는 (조회한 판례들의 참조판례에 반복 등장 여부)·(중요판례 표시)를 활용하세요.

#### 직접 사례 부족 시 한계점 표기 형식 (SKILL 5.5단계 참고)

1차·2차 재시도까지 마쳤음에도 직접 사례가 부족한 경우, 다음 **두 위치**에 한계점을 반드시 명시합니다.

**1) 첫머리 — "검색 조건" 절 다음, "정리된 답변" 절 앞에 별도 알림 박스로**:

```markdown
> ⚠ **검토 한계 안내**: 본 답변은 사용자 질의의 정확한 사실관계를 다룬 직접 판례가 검색 범위에서 충분히 발견되지 않아, 관련 분야의 대법원 법리를 유추 적용하여 작성되었습니다. 결론은 일반 법리를 토대로 한 추정에 가깝고, 동일 쟁점에 관한 직접 판례가 존재할 가능성을 배제하지 않습니다. 자세한 내용은 마지막 "검토 한계" 섹션을 참고하세요.
```

**2) 마지막 — "검토 한계" 섹션**: 다음 항목을 순서대로 기재.

```markdown
## 검토 한계

- **시도한 검색어 (검색 차수별)**:
  - 원검색: <검색어>
  - 1차 재시도: <검색어> (변경 사유: <...>)
  - 2차 재시도: <검색어> (변경 사유: <...>)
- **검토한 판례 수**: 페이지 순회 누적 N건, 본문 visit M건, 추가 조회한 상급심·참조판례 K건.
- **직접 사례 부족의 이유**: <사실관계가 동떨어진 사례만 발견 / 검색어는 일치하나 쟁점이 다른 사례가 다수 / 핵심 쟁점에 대한 대법원 선례 미발견 등>.
- **추가 검색·자문 제안**:
  - 권장 키워드 후보: <...>
  - 다른 자료원: lbox.kr(lbox-case-search), 대법원 종합법률정보, 국가법령정보센터 등.
  - 전문가 자문: 사안의 정확한 결론을 위해서는 해당 분야 전문 변호사 자문 권유.
```

두 위치 모두 명시하는 것이 원칙입니다. 한 곳만 적으면 사용자가 한계를 놓칠 위험이 있습니다.

#### 병합 보고서 (사이트를 지정하지 않은 조사 — SKILL 1단계)

사이트를 지정하지 않은 조사를 보고서 하나로 합칠 때는 위 양식을 그대로 쓰되 다음만 바꾼다. 이 절은 lbox-case-search·bigcase-case-search의 report-format.md에 같은 문언으로 있다.

1. **검색 조건**: 첫 줄에 `- 검색원:`을 두고 원천마다 검색어·필터·조회 범위를 적는다 — `판례DB(검색어 …) · lbox.kr(검색어 …, 필터 …, N페이지) · bigcase.ai(검색어 …, 필터 …, N페이지)`. 원천별 검색어·필터가 같을 때만 아래 `검색어`·필터 줄로 합친다. 한쪽 사이트가 막혔으면 그 자리에 `bigcase.ai — 로그인 만료로 미검색`처럼 적는다.
2. **첫머리 알림**: 한쪽이 막혔거나 직접 사례가 부족하면 "검색 조건"과 "정리된 답변" 사이의 알림 박스 **하나**에 함께 적는다(예: `> ⚠ **검토 한계 안내**: bigcase.ai 로그인 만료로 lbox 결과만 반영했습니다. …`).
3. **참고 판례**: `법원·선고일자·종류` 다음 줄에 `- **원천**: 판례DB | lbox | bigcase`(둘 이상에서 확인했으면 `lbox·bigcase`처럼)를 둔다. 요지 칸 이름은 `판결요지`로 통일하고 bigcase의 재판요지도 이 칸에 적는다. `원문`에는 확인한 원천의 URL을 모두 적는다(`https://lbox.kr/case/…` · `https://bigcase.ai/cases/…` — 판례DB만이면 `판례DB {case_id}`).
4. **선례표**: 열을 `| 선례 | 법리 | 선례성 근거 |`로 하고, lbox는 `인용 N·따름 판례 N`, bigcase는 `참조판례 반복·중요판례`, 판례DB는 `피인용 N`으로 적는다.
5. **검토 한계**: "시도한 검색어"와 "검토한 판례 수"를 원천별로 나눠 적는다(`lbox 원검색: … / bigcase 원검색: …`).
6. **파일명**: `case-search-<주요키워드>-<YYYYMMDD>.md`.
