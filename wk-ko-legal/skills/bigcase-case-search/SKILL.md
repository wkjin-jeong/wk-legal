# bigcase-case-search

bigcase.ai(빅케이스) 판례 검색 사이트에서 사용자 질의와 관련된 판례를 자동으로 검색하고, 본문을 조회하여 사용자 질의에 답하는 markdown 보고서를 생성합니다.

> **검색·본문 모두 직접 URL로 동작합니다 (2026-07 라이브 검증본).** bigcase는 lbox(2026.6 개편 후)와 달리 컴포저·작업(Task) 개념이 없고, 검색은 `https://bigcase.ai/search/case?q={키워드}` URL, 본문은 `https://bigcase.ai/cases/{법원명}/{사건번호}` URL로 바로 접근합니다. 필터도 URL 파라미터로 결정적으로 지정할 수 있어 흐름이 단순합니다.

## 사전 조건 및 환경 점검

작업 시작 전에 빠르게 점검하세요.

1. **Chrome 실행 + bigcase.ai 로그인 필수**: 유료 구독 계정으로 로그인되어 있어야 판례 전문 열람이 자유롭습니다. 사용자가 Chrome에서 미리 로그인해 두었다는 전제로 동작합니다. 이 Skill은 Chrome 확장(Claude in Chrome)의 계정 기반 연결로 작동하므로 Claude가 동작하는 PC와 Chrome이 실행되는 PC는 같을 필요가 없습니다. 단 bigcase.ai 로그인은 Chrome이 실제 실행 중인 PC에서 사용자가 직접 마쳐 두어야 합니다.

2. **Chrome MCP 도구 선택**: `mcp__claude-in-chrome__*`(`navigate`, `javascript_tool`, `read_page`, `computer`, `tabs_context_mcp` 등)를 사용합니다. bigcase는 URL 직접 진입이 가능하므로 대부분 `navigate` + `javascript_tool` 두 가지로 충분하며, `computer`(클릭)는 기간 드롭다운 등 일부 필터 조작에만 필요합니다.

3. **연결된 브라우저 확인 + 선택**: `list_connected_browsers`로 연결된 Chrome 인스턴스를 확인하고, 여러 기기가 연결되어 있으면 어느 기기에서 bigcase.ai에 로그인했는지 사용자에게 확인한 뒤 `select_browser(deviceId)`로 지정합니다. 각 대화는 `tabs_context_mcp{createIfEmpty:true}`로 전용 탭을 확보한 뒤 그 `tabId`로 작업합니다.

4. **JS 실행 사전 점검**: 첫 페이지에서 `document.title` 등을 평가해 정상 응답이 오는지 확인합니다. 실패하면 사용자에게 확장 권한·연결 상태 점검을 요청하고 중단하세요.

> **자물쇠 아이콘 안내**: 검색 결과 카드 일부에 자물쇠 아이콘이 표시되지만, 구독 계정으로 로그인된 상태에서는 해당 판례도 전문이 정상 열람됩니다(실측). 본문 섹션이 비고 "빅케이스Plus 시작하기" 류 구독 유도만 보일 때만 구독·로그인 상태를 의심하세요(`references/troubleshooting.md`).

## 작업 흐름

### 1단계: 사용자 의도 파악

사용자 질의에서 다음을 추출합니다.

- **검색어 (필수)**: 핵심 법률 쟁점/키워드. 자연어로 길게 물어봐도 검색에 적합한 짧은 키워드로 선정합니다. (예: "회사가 갑자기 해고했는데 부당해고로 인정될 수 있나요?" → "부당해고")
- **사건유형 (선택)**: 민사/형사/행정/헌법/특허/가사 → URL `case_type` 파라미터.
- **법원 (선택)**: '대법원' 명시 시 → URL `court=1000`.
- **재판유형 (선택)**: 판결/결정 → URL `decision_type`.
- **선고기간 (선택)**: '최근 1년/3년/5년' → 기간 드롭다운 UI로 적용.

파라미터 값 표와 적용 방법은 `references/extraction.md` 1장을 따릅니다. 명시되지 않은 선택 파라미터는 적용하지 않습니다. 질의가 모호하거나 검색어 선정이 불확실하면 진행 전에 한 가지만 사용자에게 확인하세요.

### 2단계: 검색 실행 (직접 URL)

`navigate`로 `https://bigcase.ai/search/case?q={encodeURIComponent(검색어)}`(+ 선택 파라미터)에 바로 진입합니다. 상단 탭은 **판례**가 기본이며, 문서범위 칩(전문판례/미리보기 판례/전체)은 기본값 **전문판례**, 정렬은 기본 **관련도순**을 그대로 사용합니다.

> **navigate 후 짧게 대기**: 진입 직후 곧바로 JS를 실행하면 렌더링과 충돌해 `Runtime.evaluate timed out`이 날 수 있습니다. `navigate`와 추출 `javascript_tool` 호출을 분리하고 사이에 짧은 텀을 두세요.

### 3단계: 결과 카드 추출 및 페이지 순회

결과 목록은 `.page-search-list__list-wrap` 안의 카드 `.search-list-card`(루트 div)입니다. 카드에는 링크가 없고(JS 내비게이션), **제목 텍스트**("{법원} {선고일} 선고 {사건번호} 판결 {사건명}")를 파싱해 법원·사건번호를 얻어 본문 URL을 구성합니다. 카드 하단에 **주문 결과 배지**(파기환송/원고승/원고패/기각 등), 본문에 **검색어 하이라이트 스니펫**이 있습니다. 추출 JS·총 건수 확인은 `references/extraction.md` 1장을 따릅니다.

#### 페이지 순회 정책

- 결과는 **10건/페이지**, `&page={N}` URL로 직접 이동합니다(하단 번호 페이지네이션도 실제 링크). 정렬은 기본 관련도순입니다.
- **항상 최소 3페이지(상위 30건)까지** 살펴봅니다.
- 3페이지까지 누적 결과 중 **High 관련성 판례가 10건 이상**이면 멈춥니다. 미만이면 4페이지부터 한 페이지씩 더 진행하여 (누적 High ≥ 10) 또는 (마지막 페이지 도달)에서 멈춥니다.

#### 스니펫 1차 관련성 판단 (snippet triage)

본문 visit이 비싸므로, 카드의 **스니펫·주문 배지**만 보고 1차 관련성을 매깁니다.

- **High 후보**: 핵심 쟁점이 스니펫에 직접 드러난 카드. 대법원 판례는 우선순위를 높입니다.
- **Medium 후보**: 검색어는 일치하지만 쟁점이 약간 다르거나 스니펫만으로 판단이 어려운 카드.
- **Low**: 검색어만 우연히 맞고 쟁점이 명확히 다른 카드. visit을 건너뛰고 사건번호만 모아둡니다.

> bigcase 카드에는 lbox와 달리 **인용 수·조회 수가 없습니다.** 선례성 가중은 본문 visit 후 참조판례·상하급심 정보로 보완합니다.

본문은 **High + Medium 후보만** visit합니다.

### 4단계: 각 판례 본문 조회

`https://bigcase.ai/cases/{법원명}/{사건번호}`(각 부분 `encodeURIComponent`; 법원명의 공백 — 예: "춘천지방법원 강릉지원" — 도 그대로 인코딩하면 정상 작동)로 `navigate`합니다.

본문은 일반 DOM으로 **전문이 한 번에 렌더**됩니다(전원합의체 약 6만 자 실측, 가상화·중복 렌더 없음). 섹션은 `[class^="CaseParagraph_container"]` 단위이고 섹션 제목은 다음과 같습니다(`references/extraction.md` 2장).

- **대법원(공보 수록) 판례**: 판시사항 · **재판요지**(lbox의 판결요지에 해당) · 참조조문 · 참조판례 · 주문 · 이유.
- **하급심(미공보) 판례**: 주문 · 청구취지 · 이유 등 축소 구성(판시사항·재판요지 없음)이 보통입니다.
- 머리 정보(법원·선고일·사건번호·사건명·주문 결과·중요판례 표시)는 `document.title`과 `[class*="CaseContentInfo"]`에서 회수합니다.

**적재(완전성) 판정**: '이유' 섹션이 존재하고 그 끝이 결론부("…주문과 같이 판결한다", "…의견을 밝힌다" 등)로 끝나면 정상입니다. 섹션이 0개이고 구독 유도 문구만 보이면 로그인·구독 상태를 의심하세요(특정 한 건만 비면 건너뛰고 진행 상황을 한 줄로 알림).

### 4.5단계: 관련 판결 추적 (필수)

본문 페이지 우측 사이드바와 본문 내 링크에 관련 자료가 구조화되어 있습니다(`references/extraction.md` 3장).

- **상하급심 판례**: 사이드바 "상하급심 판례 N" — 각 항목이 실제 `<a href="/cases/…">`이고 현재 사건에는 `clicked` 클래스가 붙습니다. **lbox와 달리 관계 라벨(파기환송/상고기각 등)이 없으므로**, 관계·결론은 각 본문의 주문에서 확인합니다.
- **참조판례**: 본문 '참조판례' 섹션과 '이유' 안의 인용 판례가 모두 실제 `/cases/…` 링크입니다.
- **AI 유사판례**: 사이드바 "Ai 유사판례" — 사실관계가 닮은 사례 발굴에 활용.
- **관련 논문**: 사이드바 "관련 논문 N" — 학술 문헌 제목. 필요 시 보고서에 참고 목록으로만 기재(본문 대체 금지).

##### (가) 상급심 판결의 의무적 조회 — 하급심 본문을 visit한 경우 반드시 적용

**대법원이 아닌 하급심 판례의 본문을 visit한 경우, 사이드바 "상하급심 판례"에 그 사건의 상급심이 있으면 그 상급심 본문도 반드시 함께 조회합니다.** 예외 없는 필수 절차입니다. 같은 사실관계에 대해 상급심이 결론을 뒤집을 수 있고(특히 파기환송), 하급심만 보고 답변을 쓰면 잘못된 결론을 전달할 위험이 큽니다.

절차: ① 체인에서 상급심 URL 확인 → navigate, ② 다단계면 **가장 상급심까지** 추적, ③ 각 상급심의 주문·핵심 이유를 확인해 하급심과 어긋나는지 점검, ④ 뒤집힌 경우 답변에는 **상급심 결론을 우선** 사용하고 하급심은 "원심/환송 전 판결"로 위치지어 인용("결론" 항목에 흐름 명시).

##### (나) 참조판례의 추적

핵심 대법원 선례가 '참조판례'에 링크되어 있으면 "참조 대법원 선례 정리" 표에 기록하고, 반복 인용되는 선례는 본문도 visit해 정확한 판시사항·재판요지를 확보합니다.

### 5단계: 관련성 필터링 (강화)

본문 visit이 끝나면 각 판례를 본문 기반 최종 관련성으로 재분류합니다(스니펫 High라도 본문 확인 결과 쟁점이 다르면 강등, Medium이 본문에서 쟁점을 정면으로 다뤘으면 승격).

- **직접 관련(High)**: 질의 쟁점을 정면으로 다룬 판례 → "참고 판례"에 전부 포함.
- **간접 관련(Medium)**: 쟁점·맥락이 약간 다른 판례 → 비교 가치가 있을 때만 한 줄 요지로 언급.
- **관련성 낮음(Low)**: "정리된 답변"·"참고 판례"에서 제외하고 별도 섹션에 사건번호만 모아둡니다.

이 Skill의 가치는 링크 나열이 아니라 **사용자 질문에 답하는 것**입니다. 노이즈 판례를 끼워 넣으면 답변 품질이 떨어집니다.

### 5.5단계: 직접 사례 부족 시 재검색 정책

본문 visit과 관련 판결 추적이 끝난 시점에 질의의 정확한 사실관계/쟁점을 다루는 "직접 사례"가 충분한지 점검합니다. (핵심 쟁점 정면 판례 1건 이하 / 발견 선례의 사실관계가 동떨어짐 / High 다수가 "검색어 일치"일 뿐 "쟁점 일치"가 아님) 중 하나면 부족으로 판정하고 키워드를 바꿔 재검색합니다(2~4단계 재실행 — 새 `?q=` URL로 진입만 하면 됩니다).

- **1차 재시도**: 좁은↔넓은 키워드 전환, 동의어·상위어·하위어, 사건유형·법원 필터 추가.
- **2차 재시도**: 1차와 다른 방향으로 변경.
- 진행 전 사용자에게 한 줄로 알립니다: "직접 사례가 부족하여 `<사유>`를 위해 `<새 키워드>`로 재검색합니다." 결과는 기존과 **합산**하여 하나의 markdown으로 정리하고, "검색 조건"에 사용한 모든 검색어를 기록합니다.
- 2차까지도 부족하면 답변을 작성하되, **첫머리와 말미 두 곳**에 한계점을 명시합니다(형식은 `references/report-format.md`).

### 6단계: 결과 markdown 파일 작성

**저장 위치**: 사용자가 선택한 작업 폴더에 저장합니다. 없으면 outputs/에 저장하고 `computer://` 링크로 안내합니다. 절대 경로를 하드코딩하지 마세요.

**파일명**: `bigcase-search-<주요키워드>-<YYYYMMDD>.md` (예: `bigcase-search-부당해고-20260731.md`). 민감정보(실명·주민등록번호·계좌번호 등)는 파일명에 넣지 않습니다.

보고서 표준 양식은 **`references/report-format.md`를 작성 직전에 읽고 그대로 따릅니다.**

## 인용/출처 작성 원칙

- **모든 사실 진술에는 출처(사건번호)가 있어야 합니다.** 사용자가 원문을 추적할 수 있어야 합니다.
- **사건번호 표기**는 가능하면 법원명을 함께 적습니다(`대법원 2023다12345`).
- 본문에 없는 내용을 추정해서 적지 마세요. 확인되지 않은 내용은 "검색된 판례에서는 명확히 확인되지 않음"으로 표시합니다.
- 원문 링크는 `https://bigcase.ai/cases/{법원명}/{사건번호}` 형식으로 적습니다.

## 문제 발생 시

증상별 대응(검색 0건, `Runtime.evaluate timed out`, `[BLOCKED]`, truncated, `Tab not found`, 구독·로그인 문제, 셀렉터 불일치, 병합 사건번호 등)은 `references/troubleshooting.md` 참조. 핵심: ① `navigate`와 `javascript_tool`은 분리 호출하고 짧은 텀을 둘 것, ② 결과 반환 시 원시 `outerHTML`·쿼리스트링을 포함하지 말 것(`[BLOCKED]` 차단 유발 — pathname·텍스트만), ③ 해시 접미사 클래스(`CaseParagraph_container__…` 등)는 프리픽스 매칭(`[class^="…"]`)으로 잡을 것.

## 금지 사항

- 사용자가 bigcase.ai에 로그인하지 않은 상태에서 강제로 진행하지 마세요.
- 본문에서 확인되지 않은 법리를 지어내지 마세요.
- 판례를 단순 나열하지 말고 **사용자 질의에 답하는 형태**로 정리하세요.
- 검색어만 우연히 일치하고 쟁점이 다른 판례를 그대로 끼워 넣어 노이즈를 만들지 마세요.
- **하급심 본문을 visit한 뒤 사이드바 "상하급심 판례"에 상급심이 있는데도 그 상급심 본문을 조회하지 않은 채 답변을 작성하는 것은 금지**됩니다.
- **직접 사례가 부족한데도 1차·2차 재검색을 생략한 채 곧바로 답변을 작성하는 것은 금지**됩니다.
- 관련 논문의 내용을 판례 법리처럼 인용하지 마세요(문헌은 참고 목록으로만).
