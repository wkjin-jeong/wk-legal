# 로컬 실무지식베이스(LLM-wiki) 연동 정책 (공통)

민사·행정·형사 서면과 자문의견서 작성 시 사용자의 로컬 실무지식베이스(LLM-wiki)를 활용하는 규칙의 canonical 정의. 각 skill의 SKILL.md·references는 이 파일을 참조하고, 어느 자산을 어느 단계에 쓰는지만 자기 파일에 둔다. 지식베이스가 없는 환경에서는 이 정책 전체가 조용히 생략된다(6. 폴백).

## 1. 경로 규약과 존재 게이트

- 지식베이스 루트는 환경변수 `WK_LEGAL_WIKI_ROOT`가 지정한 경로, 미설정 시 `~/LLM-wiki`.
- **작업 착수 시 1회만 존재를 확인한다**(루트 디렉터리 유무). 없으면 이 정책의 모든 단계를 건너뛰고 각 skill의 기존 절차만으로 진행한다. 지식베이스가 없다는 사실을 사용자에게 별도로 보고할 필요는 없다.
- 지식베이스는 사용자의 사적 자료다. **그 내용을 플러그인 저장소·공개 산출물로 복사하지 않는다**(5.의 민감정보 방화벽).

## 2. 자산 개요

| 자산 | 경로(루트 기준) | 내용 | 용도 |
|---|---|---|---|
| 실무제요 | `minsa-sosong-{1,2,3}-2025/` | 법원실무제요 민사소송 I~III(2025년 개정판) 섹션별 markdown 변환본 | 민사소송 절차 실무의 확인·인용 |
| 서면가이드 | `서면가이드/` | 자작 서면 코퍼스에서 귀납한 구조·문체·문형 가이드(검수 상태 관리) | 서면 골격·문형·문체의 1차 기준 |
| 서면DB | `서면DB/` | 실제 제출 서면 원문 코퍼스 + 카탈로그 | 전례(선행 서면) 참조 |

## 3. 실무제요 조회 레시피

민사소송 절차(관할·송달·기일·변론·증거조사·소송종료·상소·독촉·조정 등)의 실무 확인이 필요할 때 사용한다. 행정소송 절차도 행정소송법 제8조 제2항(민사소송법 준용)의 한도에서 같은 방식으로 활용한다.

1. **권 선택**: 루트의 `_카탈로그.jsonl`로 3권의 범위를 확인한다 — 1권 총론·법원·관할·당사자·비용(제1~15장), 2권 소제기·기일·송달·변론·사건관리(제16~24장), 3권 증거·소송종료·상소·재심·특별절차(제25~40장).
2. **섹션 특정**: 해당 권의 `00_서지_목차.md`(장·절 제목 + 페이지 범위 + 파일 링크)를 읽거나 `_index.jsonl`을 keyword로 grep해 섹션 파일을 특정한다. `_index.jsonl` 스키마는 권마다 차이가 있으나(3권만 parent/prev/next 보유) `section_id`·`file`·`title`·`pages`·`keywords`는 공통이다.
3. **부분 읽기**: 섹션 파일은 큰 것이 90KB를 넘으므로 통째로 읽지 않는다. 파일 내 `<!-- p.NNN -->` 페이지 마커를 grep으로 먼저 찾아 필요한 페이지 범위만 offset 지정으로 읽는다. front-matter(`section_id`·`pages`·`cites_law`·`cites_cases`)로 섹션 좌표를 확인한다.
4. **인용 표기**: 루트의 `_인용규약.md` 형식을 따른다 — 본문 인용은 "법원실무제요 민사소송 [II] (2025년 개정판, 2026), NNN페이지". 페이지 번호는 인용 위치 직전의 `<!-- p.NNN -->` 마커로 역산한다.

주의 두 가지.

- 본문은 PDF 자동 추출본이라 **오탈자가 남아 있다**. 서면에 문장을 직접 인용할 때는 검수를 거치고, 오탈자가 의심되는 구절은 원문 대조가 필요함을 사용자에게 알린다.
- 실무제요는 2차 문헌이다. **조문은 ko-law-api, 판례는 lbox-case-search·bigcase-case-search로 재확인한 것만 인용한다** — 실무제요 본문에 인용된 조문·판례 번호를 재검증 없이 그대로 옮기지 않는다.

## 4. 서면가이드 사용 규칙

1. **진입점은 `서면가이드/00_인덱스.md`**. 서면 유형별 구조 가이드, 문체 가이드(공통·형사특칙), 문형 라이브러리의 인덱스다. 해당 작업에 필요한 가이드만 골라 읽는다.
2. **front-matter `검증상태: verified`인 가이드만 단정 적용한다.** `draft`는 참고만 하고 산출물의 규범으로 삼지 않으며, `deprecated`는 무시한다.
3. 각 skill의 references에 이식된 규범과 서면가이드가 충돌하면 **서면가이드(최신 검수본)를 우선**하되, 충돌 사실을 변경 사항 논평 또는 최종 요약에서 사용자에게 알린다(플러그인 갱신이 필요하다는 신호다).
4. **즐겨쓰는판례 선확인**: 판례 패키지를 구성하기 전에 `서면가이드/문형/즐겨쓰는판례.md`에서 이번 사건의 쟁점과 겹치는 쟁점군이 있는지 확인한다. 겹치면 그 판례를 검색 후보의 최우선에 두되, **반드시 판례 검색 스킬(lbox-case-search·bigcase-case-search)로 판시 원문·유효성을 재확인한 후에만 인용한다**(`shared/판례-인용-정책.md` 3.의 추정·기억 인용 금지 원칙이 그대로 적용된다).

## 5. 서면DB 전례 참조 규칙

같은 유형·같은 쟁점의 선행 서면(전례)을 참고할 때 사용한다. 서면가이드에 구조 가이드가 없는 유형(표본이 적은 신청서류 등)은 전례 직접 참조가 기본이다.

1. **검색은 카탈로그로**: `서면DB/_카탈로그.jsonl`을 분야(민사/행정/형사)·서면유형·사건명·인용 판례(cites_cases)로 grep/jq 검색해 후보를 좁힌 뒤 `file` 필드가 가리키는 원문을 연다. `rev_status: superseded`인 문서는 쓰지 않고 `superseded_by`가 가리키는 후속본을 쓴다.
2. **전례에서 취하는 것**: 구조(항목 배열), 논증 전개 방식, 문형, 표기 관행 — 여기까지다.
3. **민감정보 방화벽(절대 규칙)**: 서면DB 원문에는 실명·연락처·주소·등록번호·건강정보 등 민감정보가 익명화 없이 남아 있다. **전례의 당사자 실명·사건번호·개인 사실관계를 새 산출물에 옮기지 않는다.** 새 서면에 들어가는 사실은 현재 사건의 자료에서만 온다. 산출물·논평에서 전례를 언급할 필요가 있으면 "유사 전례(민사 준비서면)" 수준으로만 지칭한다.
4. 전례에 인용된 판례·조문을 재사용하려면 4.의 즐겨쓰는판례와 동일하게 판례 검색 스킬·ko-law-api 재검증을 거친다.

## 6. 폴백 (지식베이스 부재 시)

| 용도 | 지식베이스 있음 | 없음(폴백) |
|---|---|---|
| 절차 실무 확인 | 실무제요 조회(3.) | ko-law-api(민사소송법 등 조문) + 필요 시 lbox-commentary-search(주석서) |
| 서면 골격·문형 | 서면가이드(4.) + 각 skill references | 각 skill references 템플릿만 |
| 판례 후보 확보 | 즐겨쓰는판례 선확인(4.4) → 검색 스킬 재검증 | 판례 검색 스킬 직행(`shared/판례-인용-정책.md` 1.) |
| 전례 참조 | 서면DB 카탈로그 검색(5.) | 생략(references 템플릿으로 작성) |
